3. Deviations from 02-design, with reasons
------------------------------------------
V1  dra-trace-start follows the controllers with "-u <unit>" per unit of
    DRA_CONTROLLER_UNITS, not with -u 'fake-cxl-pool-controller*' (the
    glob only when dra-install started none, as in test91). Reason:
    measured in VM0 (section 5), journalctl -f resolves the glob once, at
    start, against units that have logged already; a unit that logs
    first later is never followed.
V2  Servers other than the first get trace tags "<name>.server" (the
    design does not say); the summary filters them as "server".
V3  An explicit --index 0 writes the bases 0xc1ae0000/0xc1ee0000 (equal
    to the defaults); without --index nothing is written, as designed.
V4  pool-snapshot: pool.LABEL.json for the server of the default name (or
    a server the test did not start), pool.LABEL.NAME.json for others
    (my reading of "suffix .<name> for the others", consistent with the
    config/state/log file names).
V5  Additions: pool-device-free-wait [--pool NAME]; dra-pool-names,
    dra-pool-urls; dra-py pool_slices/pool_nodes; pool-server-start
    builds fake-cxl-pool once per test (POOL_BUILT), validates --name (DNS
    label), --port, --control, --local-devices; it sets the EXIT trap only
    when it starts the first server (so a later start does not drop the
    'dra-cleanup; pool-cleanup' trap of dra-install).
V6  test11: the allNodes part of its assertion is replaced (D22 said keep
    len == 1; kept, but allNodes == True would fail with the new
    controller). test16: node list, found by the D22 grep.
V7  Deploy by hand: VM0 gets the image and the pulled images, not just a
    sentence (else the hand install never completes, see section 2); the
    two sample outputs that depend on the node count are marked
    placeholders until they can be taken from the cluster.
V8  D22's demo suite (P/plan-8-demo/demo/e2e) is not mine (P/**) and is
    live: findings are Requests R2/R3, no edits.
