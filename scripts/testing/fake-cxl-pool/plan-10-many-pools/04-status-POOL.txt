2. Configuration keys (server)
------------------------------
  name               string, default "fake-cxl-pool"; DNS label
                     ^[a-z0-9]([-a-z0-9]{0,61}[a-z0-9])?$
  discovery.control  "" (default) | qmp | hmp; applies to every host
                     whose hosts[] entry has no control of its own
  discovery.slots    []string, default empty = every slot; path.Match on
                     the slot bus name
  hosts[].slots      []string, default empty = discovery.slots; non-empty
                     overrides discovery.slots for that host

exclusiveSerialBase, discovery.names, hosts[].control.
Controller flag: -pool-name, default "" = GET /status name, and
"fake-cxl-pool" when the server reports no name.

3. Deviations from 02-design, with reasons
------------------------------------------
V1  Start log keeps "listening on http://" and adds control and slots
    when set (design: name and discovery names). Useful for test19
    diagnostics; nothing greps the old line (grep of E, docs, P).
V2  Controller publish log: "publishing pool %s for nodes %v: %d devices
    %v" replaces "publishing pool %s: %d devices %s" (one line for both
    D12 texts; only traces contain the old one).
V3  The no-node text is logged once per transition into "no reachable
    node" (publish logs only when the DriverResources change, and with no
    node they are always the empty Pools map); the label warning once per
    node for the lifetime of the controller.
V4  Run retries GET /status every sync interval until it answers when the
    pool name is to come from the server (nothing is published before the
    name is known; a controller started before its server keeps waiting
    instead of exiting).
V5  sync: a failure to list hosts or nodes now ends the round before
    publish ("ERROR: sync: list hosts: ..."), because publish needs
    the map. Before, publish ran first and the same server outage gave
    "ERROR: publish: ...".
V6  Slot patterns are validated (path.Match ErrBadPattern): new error
    texts in section 4. The design did not mention validation.
V7  D8 checks the serial only when the qemu tree device has one (the
    design: "no serial OR equal"); devices whose backend is not fcp_* are
    adopted as before.
V8  CLI "status" prints "name:  -" for an old server without a name
    (as for "state file").

8. Open points
--------------
O1  attachedBytesLocked counts the attachments of this server only; two
    servers that attach under the same host bridge of a VM can over-commit
    its fixed memory window (the second device_add then fails in qemu,
    503). Slot patterns on different host bridges avoid it (test19: A and
    B "*hb0", C "*hb1"; A and B never share a VM).
O2  A second server that shares a VM still sees the first server's
    devices in the tree: their slots are occupied (never chosen), their
    fcp_* ids raise its hotplug counter (harmless). A device of the same
    name and serial on two servers would still be adopted by both:
    unique names are the convention (D3).
O3  HMP sharing monitor.sock with vm-monitor (C3) is for E2E to verify.
O4  The real API server must accept the spec.pool.name field selector of
    ResourceSlices for the cheap path; otherwise the library filters in
    code (section 6), with the same result.
