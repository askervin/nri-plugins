plan-10: review of stream POOL
==============================
Written 2026-10-21 by the reviewer (Fable). Paths as in 00-README; P =
scripts/testing/fake-cxl-pool, N = the repository root. Read-only review
of the uncommitted working tree (branch 5jg-cxl) against 02-design D4-D17
and docs/memory/cxl/pool.md; claims of 04-status-POOL verified in the
code and by running the build, the unit tests and the linters myself.

Verdict: no BLOCKER, no MAJOR. The contract (selector shape, nothing
published without a reachable node, pool name from the server, one pool
per controller, status data unchanged) is implemented as designed and
the tests would catch a wrong selector, allNodes, a wrong pool name or a
wrong slot. Eight MINOR findings follow, most severe first.

Findings
--------
P1  MINOR  hosts[].slots: an empty list cannot give one host every slot
    P/pkg/server/views.go:217-223 (slotPatternsLocked), config.go:104-107,
    README.md:62-64.
    What: slotPatternsLocked falls back to discovery.slots whenever
    len(h.cfg.Slots) == 0, so `slots: []` on a host means "discovery's
    patterns", never "every slot". D7 says "a host's patterns override the
    discovery ones; empty = every slot", which also reads as "an empty
    host list = every slot of that host". The status file records the
    chosen meaning (default: discovery.slots) but no doc tells the user
    how to widen one host.
    Why: a server with discovery.slots ["*hb1"] that is cabled to every
    port of one VM has no documented way to say so; `slots: ["*"]` works
    but nobody would guess it.
    Fix: add "slots: ["*"] gives this host every slot" to the README
    bullet and the hosts[] comment of config.example.yaml, or make
    HostConfig.Slots distinguish absent (nil) from an empty list.

P2  MINOR  Run logs an ERROR when stopped while waiting for the server
    P/pkg/controller/controller.go:209-218.
    What: c.pool.Status(ctx) returns the context error on cancel; the
    loop logs "ERROR: pool name: server status: context canceled
    (retrying in 10s)" and then sees ctx.Done and returns nil.
    Why: a controller unit started before its server (V4 makes this a
    supported order) and stopped by systemd ends with a misleading ERROR
    line; dra-wait-node diagnostics and test19 traces show controller
    journals, and "ERROR" is what a reader greps for.
    Fix: `if ctx.Err() != nil { return nil }` before the logf.

P3  MINOR  A failed host or node listing is logged as a reconcile error
    P/pkg/controller/controller.go:258-261.
    What: sync logs the mapNodes failure as "ERROR: reconcile: list
    hosts: ...". Since D13 the same failure also skips publish (V5), so
    the stale slice has no "publish" error anywhere in the log.
    Why: README documents the publish log lines; someone asking "why did
    the slice not change" finds only reconcile errors.
    Fix: "ERROR: sync: %v" (or "ERROR: list hosts: %v") for the mapNodes
    branch; keep the publish and reconcile prefixes for their own steps.

P4  MINOR  adoptWarned grows by one key per foreign hotplug, never shrinks
    P/pkg/server/server.go:972-980.
    What: the warn-once key is host/qemu-id, and the id fcp_<name>.hp<N>
    carries the other server's hotplug counter, so every device_add of a
    same-named device on a shared VM adds a key that stays after the
    device is gone. Same pattern as the existing exclusive warning, so
    not new, but D8 doubles the sources.
    Why: bytes per plug for the uptime of the server; no correctness
    issue, and the per-plug key also re-warns after each re-plug of the
    same foreign device, which is probably wanted.
    Fix: at the end of reconcile for a host, drop its adoptWarned keys
    whose qemu id is no longer in h.tree.Type3 (or key by host/device
    name if once per device is enough).

P5  MINOR  D8's "tree device without serial is still adopted" is untested
    P/pkg/server/multipool_test.go:150-178, P/pkg/qemu/fake.go:398.
    What: TestAdoptionChecksSerial covers mismatch (skipped, warned once)
    and match (adopted). The guard `t3.HasSerial &&` at server.go:972 and
    the fallback a.Serial = d.Serial at server.go:1008 run only for a
    tree device without a serial, and qemu.Fake.PlugDevice always sets
    HasSerial, so no test reaches them.
    Why: devices plugged by vm-cxl-hotplug without serial= would stop
    being adopted if a refactor dropped the guard, and nothing would
    notice until an e2e run.
    Fix: a Fake knob (PlugDevice with HasSerial false, or a field) and a
    third case: plugged without serial -> adopted, Serial == d.Serial.

P6  MINOR  Unwrapped lines in the docs
    N/docs/memory/cxl/pool.md:67 (97 columns) and the "What the scheduler
    does" paragraph (the inserted sentence left a 112-column line:
    "...with a free device. It writes `status.allocation` (results with
    driver,"); P/config.example.yaml:69 (103 columns, the hosts[].slots
    comment). Both files are otherwise wrapped at about 78.
    Fix: re-wrap the paragraph; shorten the comments, e.g. "# the nodes
    the pool can reach (or allNodes: true)" and "# CXL slots of this host
    (default: discovery.slots)".

P7  MINOR  discoveryInfo's doc comment names its caller
    P/cmd/fake-cxl-pool-server/main.go:36-37: "..., for the start log
    line." The coding-style skill forbids documenting where a function
    is used.
    Fix: "discoveryInfo returns the discovery names, control and slots
    that are set, as ', discovery ...' clauses."

P8  MINOR  errcheck on the new status line
    P/cmd/fake-cxl-pool-client/main.go:246: golangci-lint
    --new-from-rev=HEAD reports the unchecked fmt.Fprintf (status 7 says
    so too). The eight neighbouring lines have the same form and
    w.Flush() returns the error, so this is consistent, not wrong; if the
    repository's CI lints new lines only, `_, _ = fmt.Fprintf(...)` on
    this one line avoids a red check.

E2  MINOR  Slot patterns are glob-expanded by the shell
    E/n4-cxl-shared-2/pool.source.sh:478: `for pat in $slots` expands
    the unquoted --slots value, and every slot pattern is a shell glob
    too ("*hb0", "cxlsw_ds[01]_usrp0hb0"). With no matching file in the
    current directory bash keeps the word, which is why it works today.
    Scenario: a file whose name ends in hb0 in the directory run.sh runs
    in turns the config into slots: ["<that file>"], the server knows no
    slot, and every attach of that pool fails Conflict "host ... has no
    free CXL slot" with nothing pointing at the cause.
    Fix: `read -r -a pats <<< "$slots"` and loop over "${pats[@]}" (read
    does not glob), or `set -f` around the loop.

E3  MINOR  The NoHost check of step E passes when the journal cannot be
    read
    E/n4-cxl-shared-2/test19-many-pools/code.var.sh:391-392:
    `dra-vm-command "$VM2" "journalctl ... | grep -c NoHost" && error`
    treats every non-zero status as "no NoHost": an ssh or journalctl
    failure (VM2 unreachable for a moment, unit name wrong) passes the
    check silently, and `grep -c` prints a count the test does not use.
    Fix: `n=$(dra-vm-command-q "$VM2" "journalctl --no-pager -o cat -u
    ${POOL_UNIT[pool-a]} | grep -c NoHost; true") || command-error ...;
    [ "$n" == 0 ] || error ...`.

E4  MINOR  pool-server-stop NAME leaves the stopped server in the
    port/log/host registries
    E/n4-cxl-shared-2/pool.source.sh:577-580 unsets only
    POOL_SERVER_PIDS[$name]; POOL_SERVER_PORTS, _LOGS and _HOSTS keep the
    entry, so pool-url NAME and pool-guest-url NAME print the URL of a
    server that is gone (rc 0) instead of "no server NAME" (rc 1), and a
    later pool-server-start of the same name silently overwrites them.
    dra-install and pool-cleanup are not affected (they iterate
    POOL_SERVERS, which is rebuilt from the pids).
    Fix: unset the four entries together in pool-server-stop.

E5  MINOR  Step G counts the monitor answers but asserts nothing on them
    E/n4-cxl-shared-2/test19-many-pools/code.var.sh:441-448: the
    retry-until snippet polls "info qtree -b" on VM2 and VM0 before each
    check of g-claim, so the monitors are exercised while pool-c attaches
    over HMP (C3), and a failing monitor is fatal (error inside the
    snippet exits the test). But MONITOR_ANSWERS is only printed: a run
    in which the claim was already attached at the first iteration polls
    once, before pool-c touched the socket, and still passes.
    Fix: after the loop, `[ "$MONITOR_ANSWERS" -ge 4 ] || error ...` (two
    iterations of two VMs: the attach over HMP takes several seconds), so
    that C3 is asserted, not just observed.

E6  MINOR  Header wrapping
