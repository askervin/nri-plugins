Result

Several CXL memory pools in one cluster work end to end, in the shape of
02-design: one fake-cxl-pool-server process per pool appliance, one pool
controller per server, one DRA pool each under the one driver

3 min 13 s) with three pools: pool-a on VM1 and VM2 (QMP, host bridge 0),
pool-b on VM0 (QMP, host bridge 0), pool-c on all three VMs (HMP, host
bridge 1). The regression tests test10 and test13 passed on the
three-node cluster with the new controller; test00-up of n4-cxl-shared-2

Research (01-research-multi-pool.txt)
A server attached to several pools is realistic: Xeon 6 and EPYC 9005
expose four x16 or eight x8 CXL root ports, each an independent
hierarchy (own CFMWS, own NUMA node); Microsoft's Octopus prototyped
servers cabled to two pooling devices each; appliances (H3 Falcon,
Samsung CMM-B, Liqid, UnifabriX MAX) attach one cable per host; nothing
in CXL 3.x binds a host to one fabric manager. Advantages: capacity
beyond one appliance, bandwidth over several host bridges, per-pool
blast radius, a rack pool for capacity plus a global pool for sharing.
Costs: lanes, cable length, two management planes, more NUMA nodes.
The recommended emulation mapping is test19's.
