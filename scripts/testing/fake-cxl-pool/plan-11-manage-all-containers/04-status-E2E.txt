E/dra.source.sh (section "Containers of pods, and leases of pool memory",
after dra-mems-wait)
- New script API helper dra-mems-fenced, and its worker dra-mems-table.

    dra-mems-fenced VMDIR NODE [NS/POD/CONTAINER...]

  Waits (retry-until, 30 s, 1 s interval) until NUMA node NODE is in
  cpuset.mems.effective of the listed containers and of no other running
  container of the node of the VM of VMDIR. Prints the table of the last
  attempt. On timeout fails the test (error) with the offender lines:
    "<label>: node N is allowed only in <list or 'no container'>, offenders:
     <offender lines>"
  or, when the listing itself failed, "dra-mems-fenced: cannot list the
  containers of <label> and their cpusets (status S)".
  Example: dra-mems-fenced "$VM2" "$CXL_NODE" "$DRA_NS/pooled-consumer/consumer"

  dra-mems-table VMDIR NODE [NS/POD/CONTAINER...]: one VM command per
  attempt, a python3 program (python3 -c, through dra-vm-command-q):
  crictl ps -q (running containers only; sandboxes are not containers),
  one crictl inspect -o json of all ids (falls back to one inspect per id
  when a container was removed meanwhile), state CONTAINER_RUNNING only,
  name from the kubernetes labels, .info.pid -> /proc/PID/cgroup (0::) ->
  cpuset.mems and cpuset.mems.effective. A container whose pid is gone
  while reading is left out; one whose files cannot be read while it
  lives is an offender. Node lists are parsed as ranges ("0-1,3", "",
  " 3\n"). Exit status 0 no offender, 3 offenders, else listing failed.
  Output, sorted, one line per running container:
    NS/POD/CONTAINER cpuset.mems MEMS effective EFFECTIVE[  <- REASON]
  MEMS/EFFECTIVE '""' when empty; REASON "has node N" (not listed),
  "lacks node N" (listed), "cannot read its cpuset: ...", and "not
  running" for a listed container that does not run (MEMS, EFFECTIVE
  "-").
