Open (02-design D12)
--------------------
O1 mempolicy (soft) mode and per-container values of containerMemory:
   the option is an object and memoryMode(pod, container) is the one
   place that resolves the mode of a container.
O2 a container that is steered and also has a pool numa claim does not
   get its pool node (cgmpolmgr owns its cpuset.mems; pool numa memory
   is not steered).
O3 region devices (BIOS/admin regions) are not fenced.
O4 pause containers and host processes keep every node.
O5 a udev rule that onlines hot-added memory would online it before the
   fence (docs require no such rule).
Also: next to an NRI resource policy that sets cpuset.mems (balloons,
topology-aware) the value must be none (NRI refuses two owners).
