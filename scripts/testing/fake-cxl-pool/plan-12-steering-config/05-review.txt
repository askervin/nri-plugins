Fix during phase 3 (orchestrator, 2026-10-23)
F1. E2E test14 failed three times: every local region created again in
    one boot failed Prepare with "probing region0 for address aliasing:
    open /dev/.cxl-probe-N/dax0.0: no such device or address" (address
    line probe of commit c55476444). When the kernel binds the first dax
    device of a new region to device_dax by itself, the driver link
    exists before device_dax has added the character device (driver core
    adds the link before probe), so an open in between gets ENXIO;
    binds that the driver makes itself go through sysfs bind, which
    returns after probe, and are not affected. Fix in
    pkg/cxl/memctl/probe.go: ProbeAliasing opens its node with
    openDaxNode, retrying ENXIO/ENODEV every 10 ms for up to 5 s; unit
    test TestOpenDaxNode (retried, other errors at once, timeout). go
    test, -race, vet, gofmt ok; golangci-lint: only the 3 errcheck issues
    of c55476444 (N2). New image
    build/images/nri-dra-driver-cxl-image-11bb350ad77a.tar (same tag
    v0.15.0-38-gc55476444-dirty). The hw run on cwf (image 21d87b11ec23)
    did not hit the race and stays valid: the fix changes nothing but the
    open of the probe.
F2. E2E test14 run 5: a steered container with DRAM-only claims (policy
    auto -> first-dram) kept an empty cpuset.mems, so it inherited every
    node, also the CXL nodes of other claims. cgmpolmgr's Start allows the
    nodes that hold memory already, and allowNodes wrote cpuset.mems only
    when a step added a node: a plan whose nodes all hold memory never
    wrote it. Older than plan-12 (DRAM claims were steered by default
    before, unnoticed because no test checked it). Fix in
    pkg/cgmpolmgr/manager.go: the first allowNodes writes cpuset.mems also
    without an added node (Manager.written); unit test
    TestAllowNodesFirstWrite. New image
    build/images/nri-dra-driver-cxl-image-2db5e4fd5d5f.tar. The hw run on
    cwf used steered containers with CXL-only claims, whose first step
    adds the CXL node and wrote cpuset.mems already: unaffected.
F3. E2E test14 run 6: steer-mix (dram 128Mi on nodes 0-1, cxl 128Mi on
    node 2, policy auto = start-interleaved) was steered but its first
    step was empty ("nothing left to steer"). Cause: with no steps given,
    minStep defaulted to maxStep = the total quota (256Mi); a step spreads
    evenly over its nodes, and no subset of nodes can take 256Mi evenly
    towards the first waypoint (64Mi, 64Mi, 128Mi), so nextStep dropped
    every node; waypointReached's tolerance (remaining < minStep) was as
    coarse. Every two-type plan with unequal per-node shares was affected
    (also first-dram with DRAM 20Gi, CXL 100Gi: no first step); only
    single-type plans worked (all tests and hw used those). Older than
    plan-12. Fix in pkg/cgmpolmgr/policy.go Plan: an unset minStep is the
    smallest increase of one node's usage between consecutive waypoints
    (from zero), at most maxStep; maxStep defaults stay (total quota).
    Single-type plans keep one step. Tests: TestPolicyPlanDefaultSteps-
    Interleaved (steps reach the waypoint exactly), TestPolicyPlanOrders
    asserts a first step for every order (the old test asserted the
    default values only), TestPolicyPlanSteps a default for one node per
    type. docs/memory/cxl/usage.md field table: minStep default. New image
    build/images/nri-dra-driver-cxl-image-a68667412e60.tar. hw: the
    steered pods there have CXL-only claims (one type): unaffected.
