  c55476444): "created region0 ... in 230.903ms" without a "bound to"
  line: the kernel binds the dax device of a later region to device_dax
  itself. Then memctl.CreateRegionSize returns as soon as
  /sys/bus/dax/devices/dax0.0/driver exists, and ProbeAliasing opens the

  the explicit switch to device_dax completes before the probe.

The failure (evidence for the Request)
  pkg/cgmpolmgr Manager.Start marks the nodes that already hold memory
  (here 0 and 1) as allowed; allowNodes writes cpuset.mems only when a
  step adds a node. A plan of DRAM nodes only adds none, so cpuset.mems
  is never written and stays "" (all memory nodes of the parent:
  effective 0-2 while node 2, the CXL node of other claims, is online).
  The NRI plugin does not fence steered containers (lend.go: the
  cpuset.mems of a steered container is cgmpolmgr's), so a steered
  container with DRAM claims only is neither narrowed nor kept off the
  CXL nodes of other claims: the plan-11 rule "no other container has the
  node" breaks for it, and 03-plan's "DRAM only lands on DRAM, cpuset.mems
  narrowed" does not hold. Steering itself works (policy interleave:0-1).
  Same in the old code (DRAM claims were steered first-dram by default
  before plan-12); with plan-12 it needs an opt-in.

The failure (evidence for the Request)
  pkg/cgmpolmgr: without maxStep the plan's maxStep is the total quota and
  minStep defaults to maxStep (Policy.Plan). Plan.NextStep skips waypoints
  that waypointReached() within minStep, and nextStep() returns no nodes
  when "no node is behind the next waypoint by at least its share of
  minStep". With start-interleaved (auto for DRAM + CXL) and minStep = the
  whole quota (256 MiB here), no node of the first waypoint (64, 64, 128
  MiB to go) is behind by its share, so the very first step is "nothing
  left to steer": the container is not steered at all (memory.high
  removed, no memory policy). Not plan-12 code; the same with the old
  default auto for DRAM + CXL claims.
