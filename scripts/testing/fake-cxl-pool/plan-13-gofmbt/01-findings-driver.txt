1.4 Container settings: steering (opt-in) and fencing
[R C/config/combine.go:104-215, D/nri.go:238-310, 355-385,
D/lend.go:739-792, D/fence.go]
- A container's results are found by the markers CXL_CLAIM_<uid>_<n>
  in its env: only the results of the requests it references. Results
  that are not prepared are left out silently (D/nri.go:382).
- A field set by several results must agree, else CC "container
  NS/POD/CTR: container.steering.policy: claim ns/a request r says X,
  claim ns/b request s says Y" (C/config/combine.go:136-139).
  defaults.container of the driver config fills unset fields.
- Steered iff the effective policy is not none AND its results have
  DRAM (dram devices) or CXL numa memory (numa local slices, regions,
  pool numa devices) (C/config/combine.go:191-215). Then cgmpolmgr
  sets cpuset.mems along the plan, the memory policy of the threads and
  memory.high per step; manager started at StartContainer
  (D/nri.go:504-523), stopped at StopContainer/RemoveContainer.
  Policy auto: first-cxl (CXL only), first-dram (DRAM only),
  start-interleaved (both).
- Otherwise, with defaults.container.fencing allowed-mems (default),
  "fenced": cpuset.mems = own - F + claimed + lent (D/lend.go:743-
  753); own = the spec's cpuset.mems, or /sys/devices/system/node/
  has_memory when the spec has none. Applied as a CreateContainer
  adjustment only if F is not empty and the value differs
  (D/lend.go:764-779). Memory policy and memory.high untouched.
  fencing none: nothing changed.
- Claim-less containers are fenced (default) or none.
- F, the fenced set: the nodes of numa local slices and of pool numa
  devices, added BEFORE their memory goes online (D/fence.go:85-108,
  D/local.go:793-795, D/pool.go:737-738); seeded at start from the
  prepared claims (D/fence.go:111-119, 143-165); ONLY GROWS until the
  driver restarts; region and DRAM nodes never.
- Log at V3: "NRI CreateContainer: ctr=C: memory steered|fenced|none
  (steering P ..., fencing F ...)" (D/nri.go:315-316); "NRI fence:
  fencing CXL node N (fenced nodes S)" (D/fence.go:101).
- Invalid container values: Prep or CC, texts doc/usage.md:675-705.
- Without NRI: claims are prepared, nothing is steered or fenced,
  lease requests fail "lending unavailable: NRI not connected".

========================================================================
2. CAPACITY AND ACCOUNTING (what the scheduler sees)
========================================================================

2.1 Sliced local memdev [R D/node_state.go:541-549, 710-739, 771-788,
D/local.go:773-785, 831-851]
- capacity.memory C = localUsableSize(U, bs). U = RAM capacity, or less
  by memdevSettings.usableSize or the probe result, rounded down to
  256Mi. With bs = 128Mi (<= 256Mi, no head subtracted):
  C = floor(U / 128Mi) * 128Mi. VM2: 1Gi = 8 blocks; VM0, VM1: 256Mi =
  2 blocks.
- requestPolicy: default C, validRange {min bs, step bs}; validValues
  [C] when C < 2*bs. A request r consumes roundUp(r, bs), at least bs;
  no request consumes C (the whole device).
- Claims fit while the sum of consumed memory of all allocated results
  on the memdev <= C. Each allocation RESULT is one slice: two
  requests of one claim on one memdev are two slices (KEY, KEY_2).
- Driver side: if the dax region has less free memory than the slice,
  Prep "... no room for the slice: N bytes free in regionX, the slice
  needs M" (D/local.go:846-848). Not expected; happens when orphan
  slices of owner "-" hold memory (2.7) or the probe shrank U after the
  allocation (doc/local.md:504-506).
- Node N grows by every numa slice and shrinks on release; dax slices
  add nothing (doc/local.md:157-165).
- With DRANodeAllocatableResources, consumed memory counts against
  node allocatable memory, and a dax claim raises the container's
  memory limit too [R doc/local.md:539-541].

2.2 Shared device, local or pool: capacity.shares = 1M, no policy. A
claim without a shares request consumes 1M = exclusive and blocks
every other allocation of the device; any share blocks an exclusive
claim; shares sum <= 1M. For a pool device this holds cluster-wide.
The node driver never checks exclusivity (D/local.go:384-416;
D/pool.go:622-633 checks shared and mode only); the pool server
refuses cross-host conflicts at attach (F/server/ops.go:533-546).

2.3 Exclusive pool device: no allowMultipleAllocations: one claim at a
time, cluster-wide; a memory request <= size fits and gets the whole
device, > size: Sched. A device that moves to another node waits for
its detach: the controller does not fail the new allocation while the
other attachment is no longer desired (F/controller/reconciler.go:
316-327).

2.4 Pool slots, invisible to the scheduler [R F/server/ops.go:562-
668]: the server picks a free slot under a host bridge with room in
its fixed memory window, else Conflict "host H has no free CXL slot"
(or "... under a host bridge with room for X", "host bridge B of host
H has no room for X more: ...") -> Ctrl reason Conflict. test19: 2
pool slots on hb0 and 4 on hb1 per VM against 2 devices per pool: not
exhausted [I]. A shared device attached to k hosts takes one slot on
each.

2.5 Region, DRAM: capacity.memory = size, no policy; a request
consumes its amount, no request the whole capacity [I: consumable
capacity semantics]. Reservation only.

2.6 Lease device: any number of claims, no capacity.

2.7 Hidden consumers: orphan slices "-" (D/local.go:708-716,
1193-1196, 1245-1262) hold region memory that the scheduler counts as
free until the next Prepare on the memdev releases them.

2.8 Placement: pool devices only on the nodes of the pool's
nodeSelector (hosts mapped by systemUUID, else by name,
F/controller/hosts.go:41-90); the scheduler pins the claim to a node
(bindsToNode) and waits for Attached until the binding timeout
(600 s), then allocates again [R doc/pool.md:278-290].

2.9 Shared NUMA node: in a VM, local slices and pool numa devices
under hb0 are all node 2. Isolation is per node: a container with any
numa memory on node 2 may allocate from all memory on node 2
[R doc/local.md:113-115, 167-169].

3.2 Driver restart: the start sequence [R D/driver.go:329-491]
  1 Pool driver: load preparedPoolClaims.json (gone memdevs only
    logged, kept until Unprepare), restoreMounts: fs node mounts and
    lease binds mounted again, unknown mounts unmounted
    (D/pool.go:252-276, D/pool_persistent.go:641-771). No sweep of pool
    regions that no prepared claim has.
  2 Local allocator: load localDevices.json; another boot: dropped
    without touching anything (D/local.go:1314-1318); Reconcile against
    the keys of preparedClaimsInfo.json (D/driver.go:557-585,
    D/local.go:1148-1241): memdev gone -> forget; Region == "" (it was
    being created) -> forget WITHOUT touching the memdev; region gone
    -> forget; claims not prepared -> released (numa offlined first;
    on failure kept as "-"); "-" slices released; dax devices of no
    slice deleted; a device without claims -> region destroyed; shared:
    unprepared claims dropped, region kept while configured shared.
  3 First scan, then nodeState: ALL CDI specs of kinds nri.io/cxl and
    nri.io/cxl-pool removed, 250 ms sleep, forgetGoneSlices (dax slices
    that the allocator does not hold lose their device node),
    cxl-claims.yaml rewritten (D/node_state.go:183-251). In this window
    the CDI devices of running claims are missing [I: a container
    (re)created then fails with an unresolvable CDI device].
  4 Fence seeded with the numa nodes of prepared claims of both
    drivers (D/driver.go:371).
  5 Broker: load leases.json, rewrite cxl-leases.yaml, listen again
    on the sockets of stored lease claims, sweep the directories of
    unknown claims (D/broker.go:133-179).
  6 kubelet plugin cxl.nri.io starts: Prepare/Unprepare may come now.
    Pool driver writes cxl-pool.yaml and starts. Slice published.
  7 NRI plugin starts; Synchronize rebuilds the container table and
    derives the management of each container from its markers and the
    prepared claims (D/lend.go:350-417); settings that do not combine:
    "NRI Synchronize: ctr=C: <error>; taken as steered".
  8 Only now lending.set(lender, broker) for both drivers
    (D/driver.go:451-461). In the window 6-8 a companion claim's
    Prepare fails with "lease ID: lending to running containers is
    disabled (--leases=false)" (D/lending.go:142-144) and a revoke
    returns nil with a warning (D/lending.go:181-186) [R; the window
    is short].
  9 Broker reconcile after Synchronize (waits at most 30 s): restarts
    interrupted releases, releases leases in Creating > 2 min and
    leases whose companion pod is gone, deleted or finished or whose
    requester is done, lends the nodes of Ready numa leases again,
    deletes companions without a lease (D/broker.go:1361-1495); then
    LendsRestored: fencing of running containers becomes ready and a
    fence pass runs (D/lend.go:797-829). Before that no running
    container is updated.
  Running containers across a driver restart:
  - fenced: keep cpuset.mems; recomputed by the first fence pass.
  - steered: managers are NOT restored: they keep cpuset.mems and their
    memory policy, are no longer throttled with memory.high and do not
    step on [R doc/usage.md:879-881; no restore path in D/nri.go].
  - numa lends: kept in the cgroups, re-applied by the reconcile.
  - dax and block fds: kept by the processes.
  - fs lease binds: kernel mounts, kept; bound again if missing.
  - regions and dax devices: kept; reconciled as in 2 (local only).
  - containers (re)created while the driver is down: no NRI adjustment
    (claim-less ones get every node; steered ones are not steered).
    After restart: fenced ones are fixed by the first pass; steered
    ones are taken as steered and never fenced or steered [R D/lend.go:
    408-417; consequence I].
  Claim unprepared while the driver is down: kubelet's
  NodeUnprepareResources fails, the pod stays Terminating (pod deletion
  waits for unprepare: K/kubelet.go:2440-2447, K/kubelet_pods.go:
  1129-1133), kubelet retries in its reconcile loop
  (K/cm/dra/manager.go:187-237) and succeeds after the restart.

3.3 Pool controller restart [R F/controller/controller.go:250-326,
F/controller/reconciler.go:125-243, 414-455]
- Stateless and level-triggered: desired attachments from the claims
  (allocation, node), actual from the server's attachments (owner
  prefix "k8s:", not Adopted). Sync every 10 s and on informer events.
- A graceful stop DELETES its pool's ResourceSlices
  (F/controller/controller.go:316-326, publisher.go:219-237). While
  they are gone: no new pool allocation, and the next rescan of
  cxl.nri.io no longer sees those serials as pool serials
  (D/pool_slices.go:62-93) [I: see E6].
- Claims allocated while it is down wait for the binding condition
  (600 s), then are allocated again; on return it attaches and writes
  Attached.
- Undesired attachments of ours: state attached -> detach; attaching ->
  later; detaching -> waited for; failed -> left alone forever, logged
  once (F/controller/reconciler.go:414-428).
- An invalid pool config gives the same AttachFailed InvalidConfig on
  every reconcile, unless the result is Attached already.

3.4 Pool server restart [R F/server/state.go:105-282,
F/server/server.go:931-1131]
- The state file keeps devices, hosts and attachments (atomic write).
  An interrupted "attaching" loads as "attached"; reconcile against
  the qemu device tree: an attachment whose qemu device is gone is
  checked for a still mapped backend, then finalized (detached) or
  marked failed "leaked: ..."; a qemu device without an attachment is
  ADOPTED (Adopted=true), which the controller ignores: it is never
  detached by the controller (F/controller/reconciler.go:171-184).
- qemu devices stay in the VMs across server restarts [I].
- While the server is down the controller's sync fails at "list
  hosts": no slice change, no attach, detach or status [R
  F/controller/controller.go sync, hosts.go:95-111].

3.5 kubelet restart [R K/cm/dra/manager.go:350-390]: the claim cache
and checkpoint survive; prepared claims are not prepared again; pods
keep running; the driver is not involved [I: plugins re-register
through plugins_registry].

3.6 containerd restart [R D/nri.go:178-180, 224-226; vendor/github.com/
containerd/nri/pkg/stub/stub.go:626-633]: the NRI connection closes
and is NEVER re-established: onClose only logs, the stub does not
reconnect, the DaemonSet has no liveness probe. Until the driver
restarts: no CreateContainer hook (no fencing of new containers, no
steering, no conflict refusal), UpdateContainers fail (lends, revokes,
fence passes). See E1.

3.7 Container crash and restart, restartPolicy Always [R D/nri.go:
238-273, 440-540; D/broker.go:1297-1359]
- kubelet creates a new container with the same CDI devices; NRI
  CreateContainer manages it afresh: fenced cpuset.mems recomputed;
  steering gets a NEW plan from its first step and a new manager at
  StartContainer (the old one is stopped by container id).
- Leases: on stop, released only if the pod is gone, being deleted,
  finished or has restartPolicy Never; otherwise kept, and the nodes
  of Ready numa leases are lent again at StartContainer; dax and block
  fds are gone (cxl-request fd --lease ID to get them again).
- dax slice contents survive (no zeroing again).

3.8 Pod deletion while Prepare runs [R K/cm/dra/manager.go:350-390,
657-700; D/node_state.go:935-945, D/pool.go:442-459]: kubelet records
the claim in its cache and checkpoint BEFORE calling Prepare; the
Unprepare comes after the Prepare (helper serialization); a failed
Prepare has rolled back; kubelet then unprepares the claim of the
inactive pod, which the driver answers with nil for an unknown claim.

3.9 Claim deletion order [I]: a reserved claim is not removed while a
pod uses it (finalizer); it is deallocated after the last consumer has
gone (after Unprepare); only then the controller detaches. Template
claims go with their pod.

3.10 Node (guest) reboot [R D/local.go:1314-1318, D/pool.go:891-915,
D/node_state.go:1030-1040; I kubelet and qemu]: local state of another
boot dropped untouched; regions are gone. kubelet keeps the claims
prepared in its checkpoint and does not prepare them again:
containers restart with the old CDI devices. Local dax slices lose
their device node and CXL_<KEY>_DAX; local numa claims keep NODE=N
without memory. The pool driver has no boot id: cxl-pool.yaml keeps
stale dax major:minor and node numbers (E7). qemu keeps hot-plugged
devices across a guest reboot [I].
