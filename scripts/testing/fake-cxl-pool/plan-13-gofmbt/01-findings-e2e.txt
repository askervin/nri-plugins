1. How a test runs
------------------

1.1 Discovery (E/run_tests.sh)

- Argument: a *.test-suite dir, or POLICY, POLICY/TOPOLOGY or
  POLICY/TOPOLOGY/TEST under one (run_tests.sh:168-198).
- Every level (suite root, policy, topology, test) goes through
  export-and-source-dir (133-138): *.var and *.var.* files become
  exported variables, *.source and *.source.* files are sourced before
  the test code, vm-files/ becomes vm_files.
- *.var rule (48-83): the variable name is the file name up to the
  first ".var"; names ending in "~" or containing "#" are skipped.
  "code" and "py_consts" are appended level by level; any other
  variable is created once and a deeper level overrides it only if it
  came from a var file, never if the user set it in the environment.
  *.var.in.* files are expanded with eval echo -e (76-77).
- Consequence for test90: code.var.sh is the test; any other
  X.var.* file in the test dir exports X; any *.source* file is
  sourced by bash. A Go model must not be named like that
  (model.var.go would export "model", x.source.go would be sourced).
- Source order: E/lib/test.bash first (253), then suite, policy
  (dra.source.sh), topology (T/cxl.source.sh, llm.source.sh,
  pool.source.sh in glob order), test dir (source-source-files,
  115-131). Topology var files: topology.var.json, vm_network.var.sh
  ("cxl-pool"), kernel_config.var.sh, kernel_getsource.var.sh.
- A test is a dir TOPOLOGY/test* (312); the test filter is a
  substring regex of its name (316).
- Long tests: SKIP_LONG_TESTS=${skip_long_tests:-yes} (5). When yes, a
  test whose whole TEST_DIR path matches *fuzz*, *long* or *stress* is
  skipped (323-338). "test90-gofmbt-reliability" matches none, so it
  would run in every run of the suite
  (./run_tests.sh memory.test-suite/dra-driver-cxl). SKIP_LONG_TESTS is
  not exported (5): the code sees only $skip_long_tests, if the user
  exported it.
- No per-test timeout in run_tests.sh or run.sh (run_tests.sh:354-355
  is a plain call piped into tee).
- Precedent of a generated test: policies.test-suite/topology-aware/
  n4c16/test06-fuzz: generate.sh runs "go run ./generate.go" offline
  (gofmbt, github.com/askervin/gofmbt/gofmbt) into generated<N>.sh in
  the test dir; code.var.sh sources each in ( ... ) & and waits, and
  exits 0 with a warning if none were generated. gofmbt is in N/go.mod
  (line 6, v0.0.0-20260730061456-f663bfa65cdf) and in N/vendor
  (modules.txt:4; vendor/ is untracked in git). cxl-tools-install
  builds Go on the host from a test too (cxl:22).

1.2 run.sh and the code

- run_tests.sh runs, per test (354-355):
    policy=... test_outdir=... TEST_DIR=... TOPOLOGY_DIR=...
    POLICY_DIR=... run.sh test 2>&1 | tee $test_outdir/run.sh.output
  test_outdir = $OUTPUT_DIR/<suite>/<policy>/<test> (347); OUTPUT_DIR is
  the output dir of the VM (310). test_outdir is mkdir -p'd, never
  cleaned (349): files of earlier runs stay (O/test14-dra-local-memdev
  holds 8 nri-dra-driver-cxl.vm.<pod>.log of earlier runs).
- run.sh per test: vm-setup and vm-nri-plugin-deploy (308-310; the
  playbook imports the newest driver image into VM2), then
  test-user-code (335-343): "kubectl delete pods --all --now" in
  namespace default (336), then ( eval "$code" ) (340), the source
  lines plus code.var.sh in a subshell of run.sh. Every run.sh variable
  is visible to the code.
- Variables of the code: TEST_DIR, TOPOLOGY_DIR, POLICY_DIR
  (run_tests.sh:354), TEST_OUTPUT_DIR (= test_outdir, run.sh:41),
  COMMAND_OUTPUT_DIR (TEST_OUTPUT_DIR/commands, 42), OUTPUT_DIR (VM2's
  output dir, 35), VM_HOSTNAME (167), POLICY = dra-driver-cxl (168),
  SSH, SCP (175-176), distro, k8scri, nri_resource_policy_src (179),
  topology, vm_network, SCRIPT_DIR, LIB_DIR, and every variable the user
  exported for run_tests.sh (run.sh is a child process): the way to give
  test90 parameters (steps, seed, ...).
- Verdict: a non-zero exit of the subshell sets TEST_FAILURES (341);
  run.sh appends "Test verdict: FAIL" or "PASS" to summary.txt and
  prints it (1166-1173). run_tests.sh greps run.sh.output for "Test
  verdict: SKIP" first, then PASS, then FAIL, else ERROR (362-371). A
  test that prints "Test verdict: SKIP ..." and exits 0 is SKIP
  (t19:44-47). The suite run exits 1 on any FAIL or ERROR (398-400).
- error MSG (E/lib/vm.bash:51-54) prints and exits 1. command-error
  MSG (E/lib/command.bash:77-93) prints COMMAND, COMMAND_OUTPUT,
  COMMAND_STATUS and exits 1 unless INTERACTIVE_MODE (breakpoint,
  run.sh:318-333). Both end the test only in the test's own shell:
  inside $(...), a pipeline or ( ) they end only that subshell.
  Evidence: helm-launch's port forward calls vm-run-until inside $(...)
  (vm.bash:1420-1422); every dra-install prints "error: waiting for
  command ... timed out after 5 s" and goes on
  (O/test19-many-pools/run.sh.output:816, P/plan-10-many-pools/
  06-runs.txt:55-58). The YAML helpers (dra-claim-yaml, ...) are used
  inside "$(...)": their error() leaves partial YAML for dra-apply.
- retry-until (E/lib/test.bash:28-73) never fails the test (returns 1);
  vm-run-until (vm.bash:1256-1283) calls error on timeout.
- verify/pyexec (run.sh:975-1135) work on the policy cache; the cxl
  tests do not use them.
- Logging: vm-command and vmdir-command print the command and its
  output and write $COMMAND_OUTPUT_DIR/NNNN-<vm> (command.bash:22-75);
  the -q variants are silent and write nothing. The counter is a shell
  variable (command.bash:19, 29): a command run in a subshell does not
  advance it for the parent. vm-command (not
  vmdir-command) also parses every command for E2EISH records
  (vm.bash:844, lib/e2eish.bash:108-130; e2eish=0 turns them off).

1.3 Background processes and cleanup

- Allowed: the code is a subshell of run.sh, background jobs are its
  children. Precedents: pool-server-start runs the server with &
  (pool:516-518), keeps the pid, pool-server-kill stops it (TERM, KILL
  after 10 s, wait; pool:540-557); dra-trace-collect starts every
  stream as "setsid bash -c ... &" (dra:2902), dra-trace-stop kills the
  process groups on the host and the sessions in the VMs (dra:3028-
  3075, DRA_TRACE_KILL dra:158); test06-fuzz runs generated scripts in
  ( ... ) & and waits. No coproc or mkfifo exists anywhere in E.
- stdin: vm-command and vm-command-q give ssh the command on stdin with
  <<< (vm.bash:852, 859), vmdir-command too (E/lib/k8s.bash:69, 81); the
  trace ssh uses -n (dra:2932); host-command runs bash -c and inherits
  stdin (E/lib/host.bash:9); fake-cxl-pool-client on the host runs that
  way (pool:692).
- The test's stdout goes through tee into run.sh.output
  (run_tests.sh:355): what a coprocess prints to the test's stdout ends
  up there.
- One EXIT trap, replaced, never chained: pool-server-start sets
  "trap pool-cleanup EXIT" at the first server (pool:519); dra-install
  replaces it with "$DRA_EXIT_TRAP" if set, else
  'dra-cleanup; pool-cleanup' (dra:410-417). A test that needs more sets
  DRA_EXIT_TRAP before dra-install (t17:298
  'dra-local-shared-cleanup "$VM2"') or traps again after it
  (t16:759, 772 exit-cleanup). Every test ends with the cleanup called
  explicitly and "trap - EXIT" (t19:496-499, t14:819-823,
  t17:542-546). A coprocess of test90 must be stopped in that trap.
- dra-cleanup (dra:643-663) = dra-uninstall (590-641: delete the pods
  of DRA_NS gracefully (--grace-period=2, timeout 60 s) and the
  namespace (120 s); wait <=60 s for no claims; wait <=60 s per node and
  server until no k8s:-owned attachment is left; save every node's
  driver log; helm uninstall; stop the controller units; delete pool
  slices left; dra-state-cleanup per node) + dra-trace-stop + a report
  of memdevs left. pool-cleanup (pool:592-644) runs "fake-cxl-pool-
  client guest release SERIAL" in the VM and detaches every
  non-adopted attachment of every server, deletes dynamic devices,
  stops the servers. Neither fails the test.

2.3 Local memdevs and what each VM offers

- Topologies (T/topology.var.json, S/n4-cxl-shared-0|1/
  topology.var.json): two CXL host bridges, hdm-for-passthrough.
  Host bridge 0: a switch with two 1G pool slots, a file-backed shared
  256M device (present false, /tmp/fake-cxl-pool/static-shared0.raw,
  sn 0xc1ae0000, the same file in all three VMs) and the local device
  (present false): 1G in VM2, 256M in VM1 and VM0. Host bridge 1: a
  switch with four 1G pool slots.
- The local device has serial 0xc100e2e1 in all three VMs
  (docs/memory/cxl/e2e.md:68-72); fake-cxl-pool calls it
  <vm name>.memdev1, slot cxlsw_ds3_usrp0hb0 (O/test19-many-pools/
  fake-cxl-pool-server-pool-a.log, -pool-b.log); the driver publishes
  it as memdev-c100e2e1 in the node's cxl.nri.io slice; its env key is
  CXL_C100E2E1_ on every node. A sharedDevices entry therefore names
  the local device of every node.
- Memory block size 128 MiB, DRAM NUMA nodes 0 and 1 (e2e.md:61-62):
  VM2's local device is 8 blocks, VM1's and VM0's 2 blocks.
- NUMA nodes of CXL: every region under one host bridge has the node of
  that host bridge (e2e.md:704-706): hb0 node 2, hb1 node 3 in VM2
  (P/plan-12-steering-config/06-runs-E2E.txt:58-59); node 2 on VM0 for
  b-pooled0 (P/plan-11-manage-all-containers/06-runs-E2E.txt:35-38).

  node 2.

7. Gotchas for a long randomized test
-------------------------------------
- Never force-delete a pod with pool memory (pool.md:621-626): the
  device stays half removed (zombie) until its VM restarts; the next
  test's pool-vm-reset then restarts the VM.
- Stock qemu leaves a zombie device on every detach: pool-vm-require
  insists on the patched qemu (pool:193-195, e2e.md:108-116).
- Latency floor: ~5 s scheduler binding poll per pool claim or pool
  lease, ~6 s per detach (pciehp); HMP detaches serialized (6). The
  scheduler retries an AttachFailed binding with its pod backoff,
  <= 10 s (plan-12 05-status-E2E.txt:237).
- "cxl create-region" right after a hotplug can fail once with
  "add_dev() failed"; the pool driver retries once after 3 s
  (pool.md:632-634).
- ENXIO opening a new dax device right after the kernel bound it
  (plan-12 06-runs-E2E.txt:69-99); fixed by an open retry in memctl,
  but it shows that the first region of a boot and later regions
  behave differently in the kernel.
- An offline of a numa slice or region fails with EBUSY when pages
  cannot move (pinned, DRAM full): the Unprepare fails, kubelet
  retries, the pod stays Terminating, the device stays attached
  (plan-3 03-summary.txt:117-120; plan-4 02-design.txt:187-188).
  Workloads that touch CXL memory (numa-touch.py) raise the chance.
- kubelet retried a failing Unprepare about every second (plan-7
  35-dynamic-bind-mount-review-T.txt:54; O/test16 trace-summary lines
  335-339).
- A claim that cannot be allocated keeps its pod Pending, not a failure
  (pool.md:627-628); the model must predict Pending vs Running and
  which node an unpinned pod lands on (t19 B, C, D, E).
- Steering and fencing are easy to break: plan-12 06-runs-E2E.txt:110-
  172 shows two steering bugs that test14 found (cpuset.mems "" of a
  steered DRAM-only container; no steering at all with
  start-interleaved and no maxStep).
- dra-mems-fenced checks every running container of the node: the
  model must know every claim and lease that has a CXL node, and that
  hb0 pool devices and local numa slices share node 2 (2.3).
- Log-based checks read only the current driver pod's log
  (dra:1421-1431): after a restart, CreateContainer lines of older
  containers are gone (dra-memory-wait waits 60 s and fails). Reused
  pod or claim names make log greps match stale lines: use unique names
  per step.
- Single-device / single-process globals: DRA_LOCAL_* (one local
  device), DRA_TOUCH_* (one numa-touch.py), DRA_CLAIM_*, DRA_MEMDEV,
  DRA_JSON, COMMAND_OUTPUT are overwritten by every call.
- dra-local-find works only on the first server: VM0's local device
  (pool-b) cannot be attached with dra-local-device (2.3).
- The local device serial 0xc100e2e1 is the same on every node: one
  sharedDevices entry makes all three local devices shared, and the
  env keys are the same on all nodes.
- dra-install resets everything (2.2); a driver-configuration action
  mid-run is a full teardown.
- Controller SIGTERM deletes the pool's slices (5.2): new claims of
  that pool stay Pending until the restarted controller publishes
  again (sync every 10 s); SIGKILL keeps them.
- Monitors: one QMP client per VM; pool-a and pool-b hold QMP, pool-c
  uses HMP on monitor.sock, which pool-vm-monitor uses too (t19 G
  checks both keep answering). Tests use qmp-e2e.sock for their own QMP
  (pool:127-135).
- Output growth: every pool-cxl-wait or cxl-wait LABEL writes ~120 KB
  of sysfs dump plus small files, dra-wait writes dra.LABEL.<vm>.json,
  dra-memdev-wait memdev.LABEL.<vm>.json; the driver log at verbosity 4
  and the trace grow with every step; the test_outdir is never cleaned
  (1.2). Bounded or step-numbered labels decide the disk use.
- error() inside $(...) does not stop the test (1.2): e.g. the YAML
  helpers inside "$(...)", or X=$(dra-value ...) (t14:375), which
  leaves X empty and goes on.
- A failure mid-run triggers the EXIT trap, which waits up to minutes
  (60 s per wait in dra-uninstall); leftover devices make the next test
  reboot VMs (pool-vm-reset).
- Pods must be pinned with a nodeSelector, never nodeName (e2e.md
  troubleshooting): nodeName skips the scheduler and the allocation.
- Shared memory must never be onlined as RAM on two VMs: it corrupts
  them (pool:182-184, 244-245); the CLI and driver refuse numa for
  shared devices (leases.md:256, 283).
- Releasing a region under a live erofs can crash the guest
  (t16:250); persistent fs needs erofs-utils, the model image and
  CONFIG_EROFS_FS (t16, e2e.md prerequisites): heavy for test90.
- auto_online_blocks must be offline (pool-vm-reset); a reboot action
  must set it again.
- memmap_on_memory must be off for exact node sizes
  (dra-node-size-exact, dra:892-904).
- The port-forward lookup of helm-launch costs 5 s per dra-install and
  prints an error line that is not a failure (1.2).
