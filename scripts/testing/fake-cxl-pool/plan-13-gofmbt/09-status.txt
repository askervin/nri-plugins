What is modelled (2026-10-29)
----------------------------
Cluster: vm2 (control plane), vm1, vm0; pools a (vm1, vm2; hb0), b
(vm0; hb0), c (all; hb1); per VM two CXL NUMA nodes: node 2 = hb0
(the local memdev and pool-a/b devices share it: one node per host
bridge window), node 3 = hb1 (pool-c).
Kinds (contract 2, A22): volatile pool devices xnuma, xdax (exclusive),
sdax, sro, sexcl (shared device: share rw/ro, exclusive use); local
memdev slices lnuma, ldax, lsteer (steering auto); lease (cxl-request,
local numa/dax); plain (no claim); persistent pool devices on pool-c
only: c-pmem0 (shared) and c-pmem1 (exclusive), kinds pwr (block
writer), pfsd/pfsc (fs readers, direct/cached), pbro (read-only
block), pbad (always refused), xpb/xpf (c-pmem1 block/fs), plse
(persistent leases pbw/pbr/pfd/pfc).
Profiles: full (volatile, 43 slots), fullp (full + 17 persistent),
pmem (persistent, 11), small, tiny, union.
Verbs: create, delete, crash, write, read, lease-get, lease-put,
settle; persistent: pwrite, pread, hold, unhold, pwipe; faults:
driver-kill, driver-restart, driver-kill-at (region|ns|mount|bind),
ctrl-kill, ctrl-start, ctrl-restart, server-restart, kubelet-restart,
containerd-restart.
Oracle: pods and phases, claims, attachments, regions and slices,
decoder stacks (holes, A9), driver state files, CDI, env, data tokens,
persistent content (pdevs), node mounts, lease binds, loops, leases,
fencing in mode allowed-mems (a container has its claimed CXL node and
no other CXL node with memory), memory.high of steered containers,
driver restarts and panics.
Fencing (A36-A40, 13-design-fencing.txt, implemented and reviewed
2026-10-29; model runs FR1-FR3 in 15-runs-fencing-reboot.txt): MBT_FENCING=allowed-mems|none|
switch; verb fencing-switch (ConfigMap patched, every driver
restarted); exact O5: allowed-mems D+E+(M\F), none D+M, "loose"
containers after a switch to none; kind dnuma (local numa slice on
node 2 + c-pooled0 numa on node 3 in one container) and pool-c numa
slots on every VM; coverage "mems|MODE|e=E|f=F|m=M". Stub runs in the
cluster matched the predictions, except bug-18 (a lease revoke in
mode none narrows cpuset.mems).
Node reboot (A41-A44, 12-findings-reboot.txt, 14-design-reboot.txt,
implemented and reviewed 2026-10-29): verb node-reboot of vm0 and vm1
behind MBT_REBOOT=guest|qemu (default off; a reboot step ~45 s guest,
~81 s qemu, pods back after ~2 min); bootID per VM, container device
nodes against the VM's current dax/pmem devices, decoder order
adopted after a boot; needs bug-15 to 17 fixed.
Not modelled yet: the static shared local device, a claim shared by
two pods, more persistent devices (hb0 slots are full).

Bugs (bug-NN files)
-------------------
  01 containerd restart loses the driver's NRI connection for good
     FIXED (exit on loss, restarted by the DaemonSet), verified V14, V5
  02 Linux: a region destroyed below the top of a port's decoder stack
     blocks new regions there (design limit, also on real hardware)
     NOT a driver bug; memctl names the hole; the model predicts it
  03 Linux: freed decoders keep stale sysfs (cosmetic)        upstream
  04 a steered container stays throttled (memory.high) after a driver
     crash; X2: unmanaged steered containers never fenced
     FIXED (release + fence at Synchronize, steeredContainers.json),
     verified V14
  05 NRI updates before a container has started are lost (containerd
     applies them to the spec only): a numa lease lost on requester
     restart; a fence update in the Synchronize window
     FIXED (leases seeded at CreateContainer, PostStartContainer,
     comparisons with the real cgroup), case 1 verified V5
  06 the node's ResourceSlice gone 20-30 s after a kubelet restart
     FIXED (own slice controller, SyncDelay 1 s), verified V5
  07 split, non-atomic persistence of prepared claims (review)
     FIXED (atomic writes, reconciliation at start), unit tests
  08 kube-scheduler: a pending pod waits ~5 min for a device that a
     deleted pod held during its binding wait (Kubernetes)
     FIXED locally (kubernetes 5jr-dra-requeue, 4de1561b97c), deployed
     on vm2, verified by A/B replay (3.5 s instead of 5 min); not
     proposed upstream yet (10-scheduler-requeue-fix.txt)
  09 a shared pool device attached but not prepared was published as a
     local, sliceable memdev while its pool's slices were gone (severe:
     a local claim could online shared memory as RAM)
     FIXED (sticky pool serials in poolSerials.json, hold-back, a pool
     watch every 30 s, a pool-serial check before any local region or
     onlining; two reviews, 05-review-DRV2.txt); found by L6, unit
     tests reproduce it; not reproduced on purpose in the cluster (the
     window is narrower than a step, 06-runs.txt V9)
  10 races in pkg/cxl/memctl/pmem.go behind a flaky unit test: a disk
     node read during a pfn probe; the pfn mode read too early, which
     could make a writable attach reformat a writer's namespace
     FIXED (also: create-namespace -f only on a region verified to have
     no fsdax namespace), stress-tested
  11 a pool region leaked when the driver was killed in a Prepare
     before its state save and the claim was released before kubelet's
     retry (found by the persistent executor; predicted as E2/S1)
     FIXED (preparingPoolClaims.json; review 05-review-DRV3 follow-up)
  12 a hollow region (left by 11) failed every device scan and every
     plugin start: FIXED (scan skips it; the driver deletes its own
     via the root decoder's delete_region)
  13 after a driver restart a loop device's backing file reads /pmemN:
     the driver did not recognise its own cached fs mount, and its
     holder check missed the loop: FIXED (backing by device number)
  14 a cut Prepare's region kept for kubelet's retry ended below newer
     regions; its later release left a decoder hole (FP3): FIXED
  15 after a node reboot the driver returned the prepared claims of
     the old boot: stale dax/pmem nodes (an rw container read another
     claim's pmem), numa nodes without memory, fs claims in
     CrashLoopBackOff, leases on gone memory (severe; reboot research)
     FIXED (boot id in every state file, stale claims prepared again,
     leases of another boot dropped; R2 unrestorable node mounts),
     verified by a qemu restart of vm1; review findings applied
  16 fake pool: a qemu restart let the server adopt the controller's
     new attachments without owner; they leaked for good
     FIXED (qemu identity checked after monitor calls and around
     device_add; controller takes over ownerless attachments; R5
     status rewrite), verified by a qemu restart of vm1
  17 qemu: a guest reset did not reset the CXL device DVSEC; after a
     guest reboot Linux refused every memdev
     FIXED in ~/github.com/qemu/qemu (working tree, not committed),
     verified on vm1; vm0 and vm1 run the fixed binary
  18 fencing none: a lease revoke narrowed cpuset.mems of a container

  20 kube-scheduler: a pod waiting in PreBind for binding conditions
