Design (study phase)
====================

1. The shared persistent code
-----------------------------
1.1 What is shared and what stays per driver
Shared (persistent.go, fsprobe.go, mount.go): the filesystem probe and
type resolution (3), the rules P4-P12 and P9 of one node (4), node mounts
(make, reuse check, upgrade, downgrade, unmount), BLKROSET of the pmem
and loop devices, the holder wait, restore of node mounts at start
(derived state, unrestored node mounts, remount), lease binds (bind,
check, unbind, stale binds, restore, sweeps), the namespace choice of a
pmem region, the block device checks by memctl and serial, CDI helpers.
Per driver: its state and files, its lock, the list of the uses of a
device on the node (the shared code is told them, it never stores them),
region creation and release (pool: memctl.CreatePmemRegionNoted with
regionNote and preparingPoolClaims.json, memctl.Release which disables
the memdev; local: the allocator and localDevices.json, ReleaseRegion,
memdev stays enabled), the facts of a device, the decision "last claim
of the device" (pool: preparedDevice; local: d.Claims), CDI spec files,
lending to the broker.
The shared object holds no device state: the superblock state and the
read-only flags are derived from the uses that the caller passes, at
every Prepare, Release and restore (contract 4 "derived, never stored").
Device operations are serialized by the caller's lock (pool p.mu, local
a.mu), which is held across them as today. The object has an internal
mutex only for its own two lists (unrestored node mounts, stale binds),
because the local driver binds leases outside a.mu.

When a node mount of the device exists (either access), its mountinfo
type is the detected type and the device is not read (no probe while a
writer may have it); a declared type must equal it (P3, found = that
type). P5 reads Filesystems each Prepare ("nodev\t<t>": refused; a type
not listed is tried, the kernel may load a module; P11 if it fails).

1.5 Prepare of one use: the state machine (contract 4)
Order of checks, before anything is touched: type (1.4); P4 (FsTypes);
P5; P6 (rw and read-only class); default access ("" -> direct for DAX
types, else cached); P7 (explicit direct, no DAX); P8 (rw, not
SingleHost: needs cluster() and Coherent, reasons of P8); P9 over others
(the uses of the serial); P10 only when a new read-only superblock is
made (ext4 Ext4NeedsRecovery; also EROFS from the mount itself).
P9 with W = a writer in others, A = accesses of the fs uses in others:
  - w fs, W fs with access a != w.Access          -> P9a
  - w fs writer, A = {direct, cached}             -> P9b
  - w fs writer, A = {the other access} only      -> P9d (Request A1)
  - w block writer with any other use, or w next to a block writer
    (F1 makes block writers exclusive: defensive) -> P9c (Request A2)
Derived state after w joins: writer := W or w.writer(); per node mount:
superblock rw iff writer (there is at most one access then); block
devices (pmem and the loop of a cached mount) read-only iff no writer.
Steps (the logs of contract 4 at V(0)):
  block:   BLKROSET pmem := !writer (0 before a writer's open).
  fs, the node mount of (serial, access) exists: reuse check (source:
           pmem for direct, a loop over it by device number for cached,
           bug-13; then P12 for DAX types with direct); if w is a writer
           and the superblock is ro: upgrade = BLKROSET 0 pmem, BLKROSET 0
           loop, Reconfigure(mnt, rw); a failure: BLKROSET 1 again and
           "device 0x<serial>: remounting <mnt> read-write: <error>".
  fs, no node mount: writable types: writer -> BLKROSET 0 pmem; cached ->
           AttachLoop(pmem, writable=true) (loop opened O_RDWR, see A6),
           BLKROSET of the loop as the pmem; FsMount(source, mnt, type,
           rw=writer, mountData); reader -> BLKROSET 1 first (pmem and
           loop), then FsMount ro.
           Read-only types: BLKROSET 1 pmem, then today's path (mount(2)
           MS_RDONLY|MS_NOSUID|MS_NODEV; cached on the read-only loop).
           After the mount: P12 check (unmount, P11/P12 texts as 3).
  Any failure undoes what this Prepare made (unmount, loop release,
  BLKROSET back to the derived state without w).
Release (gone, remaining): remaining's writer R; for each node mount of
the gone uses: no remaining use of it -> Unmount (no detach; EBUSY: the
contract text "device 0x<serial>: unmounting <mnt>: <error>") and remove
its directory; else, if its superblock is rw and not R: Syncfs, then
Reconfigure(mnt, ro) ("device 0x<serial>: remounting <mnt> read-only:
<error>", EBUSY included). Then, remaining not empty: BLKROSET := R
(read-only only when every superblock of the device on the node is ro:
mountinfo of pmem and its loops). remaining empty: nothing (the region
goes). The release reconciles, it does not trust w.ReadOnly: a rw
superblock with no remaining writer is downgraded also when the gone use
was recorded read-only (an unfinished upgrade, below).
Invariant kept by every path, also restore: BLKROSET 1 never while a
superblock of the device is rw; a superblock is made rw only on a device
with BLKROSET 0; a read-only mount of a writable type only on a device
with BLKROSET 1.

1.6 Restore at start
Restore(uses, check): per serial of the uses, the derived state as 1.5
(uses only); per node mount: missing -> check(serial, blockDev) (today's
checkBlockDevice rule), then BLKROSET as derived and mount with the
derived superblock state (an existing rw writer gets rw; P10 can make it
unrestored); existing -> reuse check, then upgrade or downgrade if its
superblock state differs (a failure is logged; the next Prepare or
Release of the device reconciles again, as 1.5 always derives); then
BLKROSET per device as derived (logged failures); then the sweep of
MountsDir (unmount what no use wants, as today). Unrestored node mounts
are kept in n.unrestored (pool: no CDI devices of their claims, today's
R2 of bug-15; Remount for the Prepare again). The use types for old state
files: FsType "" of mode fs is erofs (1.7).
Pool start (newPoolDriver), order unchanged: load (FsType normalized),
loadPreparing, demoteOtherBoot, restoreMounts = Restore over the
persistent uses of p.prepared + LoopDevice updates + log of the claims
without CDI device, RestoreLeaseBinds (rebind missing binds of prepared
companions whose node mount is mounted; unmount binds under LeaseFsRoot
that no pool claim wants AND whose source is the source of a mount in the
pool's MountsDir), releaseUnfinished, updateSerials. A cut Prepare's
writer upgrade (no prepared claim has it) is downgraded by Restore when
readers stay, or unmounted by the sweep.
Then once, after both drivers loaded (driver.go, DRV-LOCAL, Request L1):
sweepLeaseBinds(union of the wanted binds of both drivers, pool.pn,
local.pn): unmount every remaining mount under LeaseFsRoot that neither
wants (binds whose node mount is gone); one that cannot be unmounted is a
stale bind of the driver whose MountsDir names its serial (bindOrigin),
else of the pool. This answers DRV-LOCAL R4 without unmounting local
binds at the pool's start, and keeps the pool's own binds swept before
releaseUnfinished as today.
Local start: DRV-LOCAL's allocator Reconcile, then Restore and
RestoreLeaseBinds with its uses (see "Interface for DRV-LOCAL").

1.7 Lease binds read-only/read-write (contract 4, 6)
BindLease, for the fs use of a companion: target <FsDir>/<Name>; the
existing checks (name, FsDir, one fs device, ValidName, "is a <t> mount
of <src>, not of <node mount>", "is the bind of another lease"). New
bind: read-only -> Mounter.BindReadOnly(node mount, target) (open_tree
OPEN_TREE_CLONE + mount_setattr RDONLY|NOSUID|NODEV + move_mount); but see
Request A3 (read-only types keep today's plain MS_BIND); read-write ->
Mount(node mount, target, "", MS_BIND, ""). Check: the bind's FsType ==
the node mount's, Source and Root equal, MountFlags have ro (or rw),
nosuid, nodev; else unmount and E4 with "read-only"/"read-write" and <t>.
UnbindLease and UnbindStale: a mount at a target is a lease bind when its
source is a block device (/dev/...) and its type one of KnownFsTypes or
FsTypes (was: erofs); else the "is a <t> mount of <src>, not a lease
bind" error as today. The ro/rw of a bind comes from the companion's use
(ReadOnly), restore binds again with the same.

5.2 Risks (test90's covered paths first)
- BLKROSET is new on the erofs path (pmem read-only while readers are
  prepared): every erofs Prepare and the restore issue it. Its failure
  fails the Prepare. test90 checks loops' ro (unchanged: the erofs loop

    a block writer).
 A3 Read-only lease binds of read-only types (erofs, squashfs) stay a

    make them rw), open_tree only for writable types. Reason: the erofs

    the result (ro,nosuid,nodev) is the same.
 A4 The lease-fs sweep split of 1.6 (contract 4 "Restart" is silent):
    each driver sweeps binds of its own node mounts at its start, one
    process sweep of the union after both. Reason: lease-fs/<uid> is
    shared by pool and local fs leases (DRV-LOCAL R4).
 A5 (orchestrator, RUN or E2E) a probe 2 on a VM before the e2e: ext4,
    xfs and btrfs mounted ro (new mount API) on a loop with BLKROSET 1,

 A6 None needed, noted: a writable loop needs /dev/loopN opened O_RDWR

 A7 gfs2: a node whose readers mounted spectator cannot upgrade (gfs2

Interface for DRV-LOCAL
=======================
The local driver calls (all under a.mu, which serializes its device
work; the binds may run outside it):
- newPersistentNode(persistentConfig{Driver: device.DriverName, Mounter:
  newSysMounter(sysRoot) (tests: the shared fakeMounter), MountsDir:
  <KubeletPluginDir>/mounts, LeaseFsRoot: <KubeletPluginDir>/lease-fs,
  FsTypes: driverConfig.fsTypes(), Filesystems: "/proc/filesystems"})
  before Reconcile. The pool gets the same FsTypes (newPoolDriver
  parameter or persistentConfig).
- Prepare of a result: its region (CreatePmemRegionNoted under its
  bookkeeping), pmemNamespace(ctx, mem, serial, pr, mode, readOnly), then
  pn.Prepare(ctx, persistentTarget{Serial, BlockDevice, Facts},
  persistentWant{UID, Result, Mode, ReadOnly, Access, FsType}, others):
  others = the uses of the serial of other claims in d.Claims and the
  uses that this claim acquired already. Store the returned use's
  FsType, Access, NodeMount, LoopDevice, BlockDevice (+ numbers,
  Namespace) in its records.
- Release of a claim's uses of a device: pn.Release(ctx, serial, gone,
  remaining) first (error: keep, the Unprepare fails); when it was the
  last claim: pn.WaitNoHolder(ctx, serial, blockDev, deadline) (one
  deadline per Unprepare), then its region release (memdev enabled).
  Before each release: gone := pn.UnbindStale(otherBind); release the
  devices of gone binds that no claim has.
- Companion claims: pn.BindLease(rec, uses, otherBind) before lending;
  pn.UnbindLease(rec, otherBind) at Unprepare after the revoke and
  before Release; on a failed Prepare UnbindLease, and pn.KeepStale when
  it fails. otherBind(target) = a prepared claim other than this one has
  target in its Lend.Mounts.
- Start: after Reconcile has dropped users of claims that are not
  prepared, and before it releases the regions of idle devices: pn.
  Restore(all prepared uses, check) where check(serial, blockDev) =
  checkPmemBlockDevice(mem, timeout, serial, ns, blockDev, major, minor)
  of the recorded namespace (or the allocator's equivalent); the
  returned loops update the records; pn.Unrestored(mnt) drives "no CDI
  device" and pn.Remount the Prepare again. Then pn.RestoreLeaseBinds(
  the prepared local companions with their fs use). The idle-device
  release must come after Restore swept the mounts dir, else the holder
  check refuses it (a cut Prepare's node mount).
- driver.go (Request L1): after newDriverState, before the kubelet
  plugins register: sweepLeaseBinds(wanted binds of both drivers,
  pool.pn, local.pn) (nil-safe for a disabled driver or unmanaged
  memdevs).
- CDI and env: fsCDIMount(nodeMount, path, readOnly),
  blockDeviceNode(dev, major, minor, readOnly); api.Memory with FsType;
  currentPmemBlockDevice for the release of a device whose recorded block
  device is not the current one (pool's releasedDevices rule).
The local driver provides: its uses as []persistentUse (built from
d.Claims slices: Mode, ReadOnly, Access, FsType, NodeMount, LoopDevice,
BlockDevice), the facts (contract 7), the otherBind function, its region
release, and never calls pn while holding s.Lock (baseState).
Answers to DRV-LOCAL 7.4: N1 yes (no device lock; an internal one for the
two lists only); N2/N3 one Prepare for both modes; N4 Release; N5
WaitNoHolder; N6 Restore + Remount + the two block device helpers; N7
BindLease/UnbindLease/RestoreLeaseBinds/sweepLeaseBinds; N8 by value;
N9 persistentUse. R3 is section 4; R4 is A4 and L1; R5 yes; R6 yes.
