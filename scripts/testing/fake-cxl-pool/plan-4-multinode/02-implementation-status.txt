4. Driver and fake pool
-----------------------
Driver (kubelet-cxl-plugin, cxl-request, doc/cxl/POOL.md, examples):
- PoolDeviceConfig (apiVersion cxl-pool.generic/v1alpha1), from the claim
  or the class, per request: mode numa|dax (numa only for exclusive
  devices, their default; dax the only mode of shared devices), readOnly
  (dax only). Strict decoding.
- The pool helper prepares an exclusive device in mode dax as a devdax
  region (no onlining, no lend), env CXL_POOL_DAX/SIZE/SERIAL_<SERIAL>;
  a device prepared in one mode refuses claims of the other mode.
- Read-only claims get the CDI device pool-<serial>-ro, device node
  permissions "r" (device cgroup rule "r"), env *_READONLY_<SERIAL>=1.
- Leases: request fields mode (memory: numa|dax), exclusive (shared),
  readOnly (dax leases); response fields mode, exclusive, readOnly. The
  broker validates the combinations, puts a PoolDeviceConfig into the
  companion claim of a dax lease, requests all "hosts" of the device for
  an exclusive lease (read from the pool ResourceSlice, filtered on the
  client), and opens the fd O_RDONLY for a read-only lease. Any Ready dax
  lease gets its fd (memory --dax too).
- cxl-request: --dax, --exclusive, --read-only, --exec for memory --dax;
  CXL_LEASE_READONLY in the environment of CMD.
- Examples read-only-shared-memory-pod.yaml (writer with all hosts,
  readers with readOnly) and pooled-dax-pod.yaml.
fake-cxl-pool (nri-plugins):
- AttachRequest.Exclusive, Attachment.Exclusive: an exclusive attach
  conflicts (409) with an attachment to another host, any attach to another
  host conflicts with an exclusive attachment, an attach of an attached
  device sets the flag (fake-cxl-pool-client attach --exclusive).
- Controller: shared devices publish hosts validValues ["1", N]; a result
  that consumes all N hosts is attached exclusively; the flag of an
  existing attachment follows its claims, and existing attachments are
  updated before new ones are made (a reader on the writer's node drops
  the flag before the readers of the other node attach); status data has
  "exclusive". Attached is written only once the attachment is exclusive.

Unit tests (all pass, also with -race for the driver): pool helper

6. Open points
--------------
- CRI-O VMs: vm-k8s-reinit passes the CRI socket of the run; untested.
- Cilium or other CNIs: refused (bridge CNI only).
- The VM network is per user and checkout; VMs of different networks
  cannot be in one cluster (vm-vmnet-record refuses).
- A VM that leaves a multi-node cluster keeps its NIC and its address,
  which do nothing in a single-node cluster.

7. Legacy programs that need a path: /proc/PID/fd/3 (2026-10-13)
----------------------------------------------------------------
Question: can a program that only opens paths use the dax fd of a lease
through /proc/PID/fd/3, without a device node or device cgroup rule?
Measured twice in the real containers of test13 (a scratch copy of it with
a probe, ~/.claude/jobs/procfd/procfd-probe.py, logs run1.log and
run2-kept.log there; the copy is removed): the exclusive writer on VM1 and
the three read-only readers on VM2 and VM1, root with the runtime's default
capabilities, device cgroup "deny all" plus the runtime defaults.
| who | path | open | result |
|---|---|---|---|
| child of the holder (inherited fd 3) | /proc/self/fd/3 | O_RDWR (writer) | EPERM |
| another process of the writer's container | /proc/HOLDER/fd/3 | O_RDWR | EPERM |
| children of the readers' holders | /proc/self/fd/3 | O_RDONLY | EPERM |
| other processes of the readers' containers | /proc/HOLDER/fd/3 | O_RDONLY | EPERM |
readlink gives /dev/dax0.0 and stat gives the char device 252:0 (root,
0600): only the open is refused, by the device cgroup of the container.
Opening the magic link is a new open of the device inode, checked like a
bind-mounted node (inode_permission -> devcgroup_inode_permission), so it
fails for the same reason. Nothing reached the device. Not added to test13.
A program that needs a path works with a claim of the pod from its creation
(test13 F: the node and the rule come with the claim), or would need the fd
without a new open, for instance an LD_PRELOAD shim that answers open() of
a chosen path with dup(3).
Kubernetes gotcha found on the way: "$$" in a container command becomes
"$" (escape of $(VAR)); write "$$$$" for the shell's pid.
