plan-5-api-consistency: implementation plan
===========================================
Written 2026-10-15 (Fable). Contract: 02-design.txt (02 below). Ground
rules: 00-README.txt. Four Opus work streams with disjoint files, then two
review agents. Paths as in 01 (D, N, P, E).

1. Streams, ownership, order
----------------------------
| stream | owns | starts after |
|---|---|---|
| S1 driver | D/cmd/kubelet-cxl-plugin/**, D/cmd/cxl-request/**, D/pkg/cxl/** (new api, device, memorypolicy; deletes discovery, cdihelpers), D/deployments/cxl/**, D/test/e2e/cxl/dra-demo-cxl.sh, D/go.mod, D/go.sum (replace directive only; vendor/ is gitignored) | S2 step 1 (memctl) is done |
| S2 pool | N/pkg/cxl/memctl/**, P/cmd/**, P/pkg/**, P/deploy/**, P/config.example.yaml, P/Makefile | at once; step 1 first |
| S3 e2e | E/dra.source.sh, E/n4-cxl/**, E/n4-cxl-shared-1/**, E/n4-cxl-shared-2/** (helpers, tests, tools); the VMs | S1 and S2 report "builds and unit tests pass" |
| S4 docs | D/doc/cxl/*.md, P/README.md, P/plan-2-dra/10-contract.md, N/test/e2e/README.md (only a sentence if needed) | at once, from 02; final pass after S1-S3 |
Each stream keeps plan-5-api-consistency/05-status-S<n>.txt (its own
file): Status (what is done, verification output), Deviations (from 02,
with reason), Requests to S<m>, Findings. S2 writes "memctl done" into
05-status-S2.txt as its first status line; S1 polls that file before
building (its own first task, the pkg/cxl/api package, needs no memctl).
Sequence:
  t0  S2 step 1 (memctl rename), S1 step 1-2 (api, device), S4 drafting
  t1  S1 steps 3-14, S2 steps 2-5, in parallel
  t2  review R1 (code vs 02) while S3 adapts helpers and tests
  t3  S3 runs the e2e tests, one at a time (section 6)
  t4  S4 final pass; review R2 (docs, e2e, leftovers)

------------------------------------------------------------------------

   CreateRegion(ctx, memdev, mode, decoder) with mode numa|dax;
   RegionInfo.Mode numa|dax; CreateDaxDeviceAt removed; the unexported

   shared, size; no pool attribute; capacities, conditions, status data

C3 driver (S1 -> S3, S4): class names and CEL of 02 section 3; the one
   class file D/deployments/cxl/device-classes.yaml; DeviceConfig fields

C5 e2e (S3 -> S1/S2 by request only): if a test cannot be written
   against C3/C4 as specified, S3 writes a Request, not a workaround.

-----------------

Steps (each ends with go build ./... and go test of the touched packages):
 1. D/pkg/cxl/api (new): types and functions of 02 8.1 with unit tests:
    Request/Response round trip, Env for every device kind of 02 5.2

    ExecEnv (DAX -> FD, CXL_LEASE), Key/RegionKey, ParseSerial/FormatSerial.
    A test asserts api.ModeNUMA == memctl.ModeNUMA and api.ModeDax ==
    memctl.ModeDax (import memctl; compiles once S2 step 1 is done; until
    then skip this one test).
 2. D/pkg/cxl/device/device.go: the constant set of 02 8.2, types Memdev
    (without Mode), DRAM, LeaseToken; delete the symbols listed as
    deleted. Delete D/pkg/cxl/discovery and D/pkg/cxl/cdihelpers (check
    with grep that no other cmd/ imports them: the GPU/QAT/Gaudi drivers
    import their own packages under pkg/<driver>/).
 3. node_state.go:
    - GetResources per 02 2.2: attributes and device names (region
      <name>-node<N>, dram, lease, memdev-<hex>); nodeAffinity of a region
      when all its memdevs agree; no name, no mode attribute.
    - PreparedDeviceInfo: DeviceType in memdev|region|dram|lease, new Mode;
      prepareLocalMemdev sets DeviceType memdev and Mode; preparedDeviceInfo
      sets Mode numa for region and dram.
    - CDI: buildClaimMarkerSpec builds one device claim-<uid> per prepared
      claim with the marker env, api.Env of every device (Memory from
      PreparedDeviceInfo: Key by serial with the per-claim slice counter,
      REGION<n> from the region name, DRAM) and the dax device nodes
      (permissions r when ReadOnly). buildLocalCDISpec, LocalCDISpecName,
      localCDIDeviceName, localEnvPrefix are deleted. prepareAllocatedDevices
      references only claim-<uid> (and lease-<uid> for lease claims).
    - removeCXLSpecs(cdiCache) at start deletes every spec of kinds
      generic/cxl and generic/cxl-pool (replaces the
      cdihelpers.AddDetectedDevicesToCDIRegistry call); delete the
      fmt.Printf at :244.
    - MemoryPolicyConfig through parseConfig (strict); error text
      "MemoryPolicyConfig: ..." on unknown fields. parseConfig called with
      an empty request matches configs whatever their requests list says
      (a MemoryPolicyConfig is per claim); with a request it applies the
      per-request rule of 02 4.1.
    - delete republish and the republish calls; Unprepare returns only the
      error.
    - NRI steering (nri.go claimedMemory): CXL nodes are devices with Mode
      numa and DeviceType memdev or region; DRAM as before.
 4. lending.go: companionLender (rename), leaseOf(claim) reads the label
    device.LeaseLabel; check(id, claim) -> hooks.OnLending(id, claim);
    parseConfig generic over kinds; deviceConfig kind DeviceConfig, modeFor
    error texts of 02 4.1; delete lendConfig and parseLendConfig; lentDevice
    unchanged.
 5. pool.go: parseConfig(DeviceConfig); CDI per claim in kind
    generic/cxl-pool, spec cxl-pool, device claim-<uid>, env by api.Env,
    device node for dax with permissions r when readOnly (delete
    poolCDIDeviceName/poolCDIDeviceID per serial; CDIDeviceID of a prepared
    device is the claim's); companion identification through the label as
    in step 4. Comments: "pool driver".
 6. local.go: delete modes snapshot (modesMu stays for blockSize), Modes(),
    modeAttribute, modeNone, modeNUMADax, localDevice.Mode and
    slicesMode()/usesDax callers that only served the attribute; the state
    file keeps "mode" per slice (needed for release). localSnapshot keeps
    BlockSize only.
 7. broker.go, lease_store.go: api.Request/Response on the wire;
    validation R1-R13 of 02 6.1 in one function with those texts;
    companion request per 02 6.5 (classes device.Class*, selectors,
    capacities, DeviceConfig per driver, labels cxl.generic/*); ops
    request, release, list, fd, env (fd and env take wait; env returns the
    lease info with env; fd additionally the fd; R13 for fd on numa);

10. cmd/cxl-request/main.go: the CLI of 02 6.1-6.4 on api.Request/Response
