Names S3 and S4 rely on (where 02 left a choice open, or differs)
------------------------------------------------------------------
- Device names: region0-node2 (a region), dram, lease, memdev-<hex>.
  At HEAD the published region name was "region0" (the map key), not
  cxl-region0-node2 as 01 1.1 says.
- Response JSON: "shared" and "readOnly" are always present (no
  omitempty, as in the 11.4 example), also in error and list wrapper
  objects; source, size, serial, node, dax, env, error, leases are omitted
  when empty. source is omitted while undecided (no --source, not Ready).
- env (S3 Q1): "cxl-request env --lease ID" prints api.ExecEnv without an
  fd: the response's env with DAX (not FD), plus CXL_LEASE=<id>, sorted
  KEY=VALUE lines. env --exec runs CMD with the same environment.
- CXL_<KEY>_SHARED (S3 Q2) is the device's sharing: 1 for a shared device
  also when the lease or claim takes it exclusively; the response field
  "shared" is the effective one (false for the writer).
- R11 and other broker refusals before a lease exists (S3 Q3): JSON line
  with "error" on stdout (request/release/list without --exec), exit 1.
  With --exec, or for env, the line goes to stderr.
- request --wait 0s answered Pending (S3 Q4): exit 0; with --exec exit 3
  (CMD needs Ready memory).
- Companion request (S3 Q5): one source -> exactly. --shared, and a
  --serial that the ResourceSlices show as a shared device, leave the
  local subrequest out, so "request --serial S" of a shared device
  (the writer) is exactly {cxl-pool-shared, serial selector, hosts = all}.
- A serial of a shared device without --mode gives mode dax (the device is
  dax only); with --mode numa: "shared memory is never onlined as RAM: use
  mode dax"; with --source local: "device 0x..: not a local device".
  "request --serial S --read-only" without --mode dax or --shared fails
  R5 in the CLI ("readOnly needs mode dax"): the CLI cannot know that S is
  shared. The test13 writer/readers of Q3 work as written in 04.
- fd and env take --wait: they wait for Ready and, unlike request, do not
  release the lease at the timeout; a lease not Ready is answered in its
  state (exit 3). fd of a numa lease (R13): "lease <id> is not a dax lease;
  use env", the response carries the lease info (mode numa), exit 3.
- R1-R10 in the CLI: "cxl-request: <text>" and the usage on stderr, exit
  2. The broker validates the same with the same function (api.Request.
  Validate), so the texts are identical; R9 and "fd needs --lease ID" keep
  the "--" spelling in the broker too.
- Extra texts (not in 02): CLI "no operation", "unknown operation %q",
  "unexpected argument %q", "unknown option --x", "--x is not an option of
  <op>", "--x needs a value", "--exec needs a command", "--shared: invalid
  value %q", "fd needs --lease ID", "env needs --lease ID"; broker
  "invalid request: <json error>" (requests are decoded strictly: an old
  client's "kind" gives `invalid request: json: unknown field "kind"`),
  `unknown op %q (request, release, list, fd or env)`, `invalid size %q`,
  `device <name> (serial 0x..) has no "hosts" capacity`, "no such lease"
  (release), "no such lease of this container" (fd, env).
- A refused companion claim fails its Prepare with an error that contains
  "claim <ns>/<name>: not the companion of lease <id>" (the drivers prefix
  it with their own "claim <ns>/<name>:" or "cxl-pool.generic: preparing
  claim <ns>/<name>:").
- DeviceConfig errors: "DeviceConfig: invalid mode %q (numa or dax)",
  "DeviceConfig: mode numa: a shared device is used as dax only",
  "DeviceConfig: readOnly needs mode dax"; unknown field:
  `DeviceConfig: invalid FromClaim config: json: unknown field "x"`;
  apiVersion: `DeviceConfig: apiVersion "v1", expected "<driver>/v1alpha1"`.
  MemoryPolicyConfig the same with kind MemoryPolicyConfig.
- Env SIZE of regions and DRAM: the consumed capacity of the claim, the
  device size when the scheduler gives none.
- Log lines of S3 Q9: all kept; "discovered local memory device
  memdev-<hex>: memN serial 0x.. size N memory block size N" (no "mode").
- Lease CLI mount: only /usr/local/bin/cxl-request; lease CDI env
  CXL_LEASE_SOCKET=/run/cxl/cxl.sock.
- CDI: generic/cxl=claim-<uid> in cxl-claims, generic/cxl=lease-<uid> in
  cxl-leases, generic/cxl-pool=claim-<uid> in cxl-pool. A companion claim

   by the CLI and the broker so the texts exist once) and
   (*Request).EffectiveMode.

   one region or on DRAM: REGION0_2, DRAM_2), and to pool claims.

   above), accepts "help", "-h", "--help", and --flag=true|false.
