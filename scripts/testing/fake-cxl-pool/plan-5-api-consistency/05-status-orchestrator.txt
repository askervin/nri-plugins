O4 (after review R1, 06-review-1.txt) Amendments to 02-design.txt; they
   are part of the contract from now on:
   A1 (R1 B1) An opaque config of the driver with an unknown kind fails
      the Prepare: "unknown kind %q (DeviceConfig or MemoryPolicyConfig)"
      in cxl.generic, "unknown kind %q (DeviceConfig)" in cxl-pool.generic.
      A wrong kind is the most likely mistake after the renames, and it
      must not silently give a read-write or numa device.
   A2 (R1 I-1) DeviceConfig on a region or dram request fails the Prepare
      when it asks for anything but numa: "DeviceConfig: mode dax: a
      region is used as numa only" (and "... dram is used as numa only";
      readOnly: "DeviceConfig: readOnly needs mode dax", as for memdevs).
      The same mismatch is an error for every device type.
   A3 (R1 I-3) CDI devices are per allocation result, not per claim:
      kubelet injects only the CDI devices of the requests a container
      references (resources.claims[].request), so one device per claim
      would hand a container that references a read-only request the
      read-write node of another request of the same claim. Name:
      claim-<uid>-<n>, n = index of the result in the claim's allocation
      (both drivers; kinds unchanged: generic/cxl and generic/cxl-pool);
      every such device carries the claim marker CXL_CLAIM_<uid>=1 and
      the env and device nodes of its own result only. Companion claims
      are treated alike by both drivers (R1 S-5): their results get no
      CDI device (the pause container references no claim).
   A4 (R1 B2) deleteOrphans selects "cxl.generic/node=<node>,
      cxl.generic/lease" and acts only on objects named cxl-lease-<value>.
   Everything else of 06-review-1.txt is accepted as written: I-2, I-5,
   I-6, S-1 to S-6 (S1 or S2 as the review says), I-4 (S2: memctl.ValidMode
