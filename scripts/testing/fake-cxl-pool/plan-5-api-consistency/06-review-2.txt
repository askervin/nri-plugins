INCONSISTENCY

I-1 D doc/cxl/LEASES.md:229-230 - owner S4
   What: the doc says "`request --wait 0s` exits with 0 whatever the state
   of the lease, unless it is Failed". With --exec that is not true. In
   cmd/cxl-request/main.go:270-273, execute() turns exitOK into 3 when the
   lease is not Ready ("CMD needs the memory"), and CMD is not started. So
   "cxl-request request --size 1Gi --wait 0s --exec prog" exits 3 and
   keeps a Pending lease. The same paragraph says "3 ... not Ready within
   --wait (request, fd, env; with --exec CMD is not started)", so the two
   sentences contradict each other for --wait 0s --exec.
   Fix: "Without --exec, `request --wait 0s` exits with 0 whatever the
   state of the lease, unless it is Failed. With --exec it exits with 3
   unless the lease is Ready at once."

I-2 D doc/cxl/USAGE.md:413-420, 438-444, 469-476, 525-532 (examples 2,
   4, 6 and 10) - owner S4
   What: example 1 (USAGE.md:401) lists CXL_CLAIM_<uid>=1 in the
   container's sorted environment. Examples 2, 4, 6 and 10 show complete,
   sorted lists without it and without "...".
   Why: since A3 every CDI device of both drivers carries the marker
   (node_state.go buildClaimsCDISpec, pool.go buildCDISpec; USAGE.md:348
   says so too), and the example pod prints "env | grep ^CXL_ | sort".
   So these lists are not what the pod prints. The pool examples (4, 6)
   copy 02 11.3, which A3 made out of date ("pool claims inject no claim
   marker").
   Fix: add the line CXL_CLAIM_<uid>=1 to examples 2, 4, 6 and 10, as in
   example 1.
