Image (cmd/plugins/dra-driver-cxl/Dockerfile), three stages:
- builder: golang:${GO_VERSION}-bookworm, same layout as memory-policy;
  make ... BINARIES=cxl-request PLUGINS=nri-dra-driver-cxl
  clean build-plugins-static build-binaries-static licenses.
- ndctl: debian:bookworm, apt build deps (gcc, meson, ninja, pkg-config,
  libkmod-dev, libudev-dev, uuid-dev, libjson-c-dev, libiniparser-dev,
  git), git clone --depth 1 --branch v85 https://github.com/pmem/ndctl,
  meson setup with -Dversion-tag=85 -Ddocs=disabled -Dasciidoctor=disabled
  -Dsystemd=disabled -Dlibtracefs=disabled -Dkeyutils=disabled
  -Dfwctl=disabled -Dtest=disabled -Ddestructive=disabled -Dpoison=disabled
  -Dbashcompletiondir=no, meson compile, DESTDIR=/ndctl meson install.
  Then cxl and daxctl and their ldd closure (fails the build on "not
  found" or a missing loader) are copied to /rootfs at canonical paths
  (realpath of the directory: /usr/lib/x86_64-linux-gnu, /usr/lib64 for
  ld-linux-x86-64.so.2, /usr/lib for libcxl/libdaxctl/libndctl), because
  /lib, /lib64 and /bin are symbolic links in distroless/static. Closure:
  libcxl.so.1 libdaxctl.so.1 libndctl.so.6 libc.so.6 libcrypto.so.3
  libiniparser.so.1 libjson-c.so.5 libkmod.so.2 liblzma.so.5 libudev.so.1
  libuuid.so.1 libzstd.so.1 ld-linux-x86-64.so.2. ld.so finds them in its
  built-in search path (no ld.so.cache needed).
  /rootfs/licenses/ndctl/ gets COPYING and LICENSES/ of ndctl, and
  debian/<package>/copyright of every Debian package of the closure.
- final: FROM gcr.io/distroless/static; /bin/nri-dra-driver-cxl,
  /bin/cxl-request, /licenses/nri-dra-driver-cxl/, /licenses/cxl-request/,
  then COPY --from=ndctl /rootfs/ / (gives /usr/bin/cxl, /usr/bin/daxctl,
  libs, loader, /licenses/ndctl/). ENTRYPOINT ["/bin/nri-dra-driver-cxl"].
  The image has no default arguments; the chart gives them.

2. Deviations from the contract (with reasons)
-----------------------------------------------
D1 RBAC: the ClusterRole is exactly D's rules (nodes get; resourceslices
   get/list/watch/create/update/patch/delete; resourceclaims
   get/list/watch/create/delete; pods get/list/watch/create/delete;
   events create in "" and events.k8s.io). Contract E's summary also
   names "resourceclaims incl. status" and "deviceclasses": D's file
   grants neither, and neither the driver (grep of
   cmd/plugins/dra-driver-cxl, pkg/cxl) nor k8s.io/dynamic-resource-
   allocation v0.37.0 kubeletplugin/resourceslice call DeviceClasses() or
   UpdateStatus/ApplyStatus of claims. Least privilege, "what D grants".
D2 Values beyond contract E's list, for parity with the other N charts:
   nri.runtime.patchConfig (+ config.*) and initContainerImage (default
   off). extraEnv values are quoted, so numbers and booleans become
   strings.
D3 Pod hardening from D kept: readOnlyRootFilesystem: true (D had it).
   D's capabilities drop ALL and seccomp RuntimeDefault were dropped:
   meaningless for a privileged container. D's env SYSFS_ROOT=/sys and
   POD_NAMESPACE were dropped (default "" means /sys; POD_NAMESPACE is
   not a flag of contract C).
D4 Additional files under /licenses/ndctl/debian/<pkg>/copyright (the
   image ships Debian's LGPL/MIT/BSD libraries, whose notices should
   travel with them).
D5 docs/deployment/helm/dra-driver-cxl.md has a short "Usage" section
   after the README include (the contract asked for a link to usage.md).
D6 Checksum annotation on the pod template (restart on config change).

4. Open issues and notes
------------------------
O1 The image build needs network access to deb.debian.org and
   github.com (pmem/ndctl tag v85, not pinned to a commit hash), like the
   go module download of the builder stage.
O2 distroless/static is now Debian 13 based; the ndctl closure comes from
   bookworm with its own glibc and loader, so there is no mixing (the
   base image has no libc).
O3 The cluster-scoped objects have fixed names (ClusterRole/Binding
   nri-dra-driver-cxl, VAP resourceslices-policy-nri-dra-driver-cxl, the
   six DeviceClasses): one release per cluster, like the other N charts.
O4 The VAP needs ServiceAccountTokenPodNodeInfo (GA since 1.32, default on
   since 1.30); without it the driver cannot write any ResourceSlice.
O5 Observation for WP1 (not a request): signal.Notify is called after
   newDriver returns; while newDriver blocks (e.g. PublishResources waits
   for the ResourceSlice informer of an unreachable API server) SIGTERM
   kills the process with exit 2 and no Shutdown (seen in V4 with docker
   stop). Harmless with a reachable API server.
O6 Not run: e2e (contract rule 8), a real cluster install.
