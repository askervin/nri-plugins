2. Deviations from the contract / task, with reasons
---------------------------------------------------
- dra-install-node takes an optional CPDIR (default the test VM) and must
  be called before dra-install of the control plane; dra-install waits
  for the recorded workers (dra-wait-node). The task allowed the reorder.
- dra-wait-node also requires $DRA_REQUEST_NODE_BIN on the node: the
  lease tests (12, 13, 15) need it, and a missing copy is easier to debug
  there than in the middle of a test. DRA_REQUEST_BIN checks are gone.
- dra-install deletes leftover DeviceClasses after the release is gone
  (see above). dra-uninstall does not delete DeviceClasses (helm does).
- New values file dra-driver-cxl.helm-values.yaml (helm-launch needs one).
- dra-uninstall saves per-node driver logs to the test output (new).
- dra-build keeps its name (tests call it) but builds only fake-cxl-pool.
- Not done (not owned): run_tests.sh lines 229-232 comment explains the
  exact-topology filter with "n4-cxl would select also n4-cxl-shared-1"; the
  logic is generic and still right, the example is now historical.
- Leftovers in existing VMs are not handled by code (rename rule: no old
  names): a transient unit "kubelet-cxl-plugin" still running from an
  old-framework run would compete with the pod (it does not survive a VM
  restart). Before the first e2e run check in both VMs:
    ssh -F test/e2e/n4-cxl-shared-{1,2}-fedora-43-containerd/.ssh-config \
        vagrant@node "systemctl is-active kubelet-cxl-plugin"
  and stop it if active. Old /var/lib/kubelet/plugins/cxl*.generic
  directories and old binaries in /usr/local/bin are harmless.
