Stream F: driver mode file (~/github.com/intel/intel-resource-drivers-for-kubernetes)
------------------------------------------------------------------------------
Owns: cmd/kubelet-cxl-plugin/**, cmd/cxl-request/**, pkg/cxl/**,
deployments/cxl/**, doc/cxl/**, go.mod, go.sum (vendor/ is gitignored).
Reads: 01-research-B-kernel-access.txt (sections on FUSE, page cache
proof), 01-research-C-integration.txt (P3, checkSamePreparation), the
plan-5 contract ../plan-5-api-consistency/02-design.txt and its
amendments (05-status-orchestrator.txt O4).
F1 Vocabulary: mode numa|dax|file in pkg/cxl/api (api.ModeFile), in
   DeviceConfig of both drivers, in the lease protocol and cxl-request
   (--mode file). Rules and texts (add them to the shared validator):
   "mode file needs readOnly: true" for DeviceConfig ("mode file needs
   --read-only" in the CLI); shared devices accept dax and file; region
   and dram refuse file like dax ("DeviceConfig: mode file: a region is
   used as numa only"). Env of a file device: CXL_<KEY>_{SERIAL,SHARED,
   MODE=file,SIZE,PATH,READONLY=1}; no DAX, no device node. api.Env
   produces PATH. A lease in mode file gets FD under --exec (as dax).
F2 Export: a node-wide FUSE export per prepared dax device in mode file,
   refcounted by the claims that use it, in both drivers (local memdev
   slices and pool devices). Mountpoint <cxl.generic plugin data
   dir>/files/<dax name>/ with one regular file "data", size = the dax
   device size, mode 0444, read-only filesystem; served in-process with
   github.com/hanwen/go-fuse/v2 (vendored; DirectMount as root, no
   fusermount3 needed; allow_other; FOPEN_KEEP_CACHE, long attr/entry
   timeouts: the content is immutable while exported); Read copies from a
   MAP_SHARED, PROT_READ mapping of /dev/daxX.Y. Prepare: device as for dax
   (region, devdax; zeroing only for exclusive/local slices as today),
   then the export, then the CDI device of the result with a mount
   {hostPath: mountpoint, containerPath: /run/cxl-files/<KEY>, options:
   [rbind, ro, nosuid, nodev, noexec]} and the env of F1;
   PATH=/run/cxl-files/<KEY>/data. Unprepare: refcount down; the last one
   unmounts (fail the Unprepare on EBUSY, kubelet retries) and unmaps,
   then the device is released as today. checkSamePreparation: dax and
   file on the same device are compatible (both are a devdax region).
   Plugin start: exports of prepared file-mode claims are re-created (a
   stale mount at the mountpoint is detached first); document that
   containers that were running keep the old connection (pages already in
   the page cache stay readable; others fail) as a limitation.
F3 Leases: the broker's companion claim carries DeviceConfig {mode: file,
   readOnly: true}; for Ready file leases the broker opens the node-side
   file O_RDONLY and passes that fd (as for dax); fd and env ops work.
F4 Docs: USAGE.md (DeviceConfig mode file, env PATH, the CDI mount, what
   "cached" means and how it differs from dax, limitations: read-only,
   whole-model populate by mmap'ing engines, plugin restart), LEASES.md
   (--mode file), POOL.md and LOCAL.md (mode file applies), README.md
   vocabulary table (mode numa|dax|file). Example
   deployments/cxl/examples/pool-shared-file-readers.yaml.
F5 Tests: unit tests for the config rules and texts, env and CDI of file
   devices, export refcounting and life cycle (an exporter interface with
   a fake in tests; the FUSE wiring itself is exercised by the e2e), the
   Read path over a fake mapping (bounds, EOF, sizes not multiple of the
   page), lease mode file, CLI validation. go vet, go test -race, gofmt,
   golangci-lint with no new findings vs HEAD, static builds.
   golang.org/x/sys is already vendored; add go-fuse with go get and
   go mod tidy && go mod vendor (the go.mod replace of nri-plugins stays
   as it is).
F6 Status: 05-status-F.txt with the exact names, texts and paths stream T
   asserts on, and "F done" when F1-F5 pass. No VM use (stream T owns the
   VMs); if a VM check is needed, write a Request to T.
