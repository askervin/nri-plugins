Decisions
---------
DF1 One word, one validator per surface. ModeFile = "file" in pkg/cxl/api; api.ValidMode,
    api.InvalidModeError and api.ErrReadOnlyMode are used by both the CLI/broker validator
    (api.Request.Validate) and the DeviceConfig validator of both drivers (deviceConfig.modeFor,
    numaOnly in lending.go), api.ErrSharedNUMA by the CLI and the broker. The texts that list the
    valid modes now list file (fixed texts, plan-5: a text names the valid values):
      invalid mode %q (numa, dax or file)                       (was "(numa or dax)")
      readOnly needs mode dax or file                           (was "... dax"; old text is a prefix)
      shared memory is never onlined as RAM: use mode dax or file   (old text is a prefix)
      DeviceConfig: mode numa: a shared device is used as dax or file only   (old text not a prefix)
    New: "DeviceConfig: mode file needs readOnly: true" and "mode file needs --read-only" (04 F1).
DF2 readOnly is explicit: mode file without readOnly is an error, nothing implies it (a later
    writable file mode can then be added without changing the meaning of a config).
DF3 Region and dram: the numa-only check comes before the readOnly rule, so mode file on them
    always gives "DeviceConfig: mode file: a region is used as numa only" (or "a dram"),
    with or without readOnly.
DF4 PATH: in a claim the container path /run/cxl-files/<KEY>/data; in a lease (env op,
    response env) the path of the file on the node, informational, exactly as DAX of a dax
    lease; --exec replaces DAX or PATH by FD=3 (api.ExecEnv). The protocol response gets a
    field "path" next to "dax" (same rule: informational).
DF5 One export table for the node, shared by both drivers, keyed by the dax device name;
    holders are (driver, claim uid): one ResourceClaim can have results of both drivers, and
    each driver releases only its own holds. No state file of its own: at start each driver
    restarts the exports of its prepared file devices (pool in newPoolDriver, cxl.generic in
    newNodeState, both before the kubelet plugins register); a device whose export does not
    start gets no mount and no PATH in its CDI device (as a dax slice that is gone gets no node).
DF6 The local allocator keeps its modes numa|dax (how a slice is bound); a claim in mode file
    gets a dax slice (zeroed as every dax slice) and the claim info records mode file.
DF7 checkSamePreparation compares numa against devdax (dax or file): dax and file claims of one
    device share its region and dax device; read-only may differ as before.
DF8 Export life cycle: Prepare = devdax as for dax, then Acquire (start on first holder);
    Unprepare = release the exports first (the last holder unmounts; EBUSY fails the Unprepare,
    the claim and the device stay, kubelet retries), then the device as today. After a
    successful unmount the plugin waits up to 5 s for the FUSE connection to end; if a copy of
    the mount in another mount namespace keeps it, the connection is aborted through fusectl
    (/sys/fs/fuse/connections/<N>/abort) and waited for again (5 s); the dax mapping is unmapped
    only after the server ended. Failed Prepares release the exports before the slices/devices.
DF9 Plugin start detaches (MNT_DETACH) every mount under files/ and removes the directories
    before any export starts; plugin shutdown (SIGTERM, driver.Shutdown) detaches the host mounts
    of running exports. Containers that ran keep their (dead) copies: cached pages stay readable,
    others fail (documented).
DF10 FUSE settings: DirectMountStrict (no fusermount), flags MS_RDONLY|MS_NOSUID|MS_NODEV|
    MS_NOEXEC, options allow_other, default_permissions, and context=system_u:object_r:
    container_file_t:s0 when /sys/fs/selinux/enforce exists (if that mount fails it mounts
    again without the context and logs a warning); FOPEN_KEEP_CACHE on open, ExplicitDataCacheControl,
    attr/entry/negative timeouts 1 h, xattrs disabled; root 0555, file 0444, owner root, times =
    export start. Read copies from a MAP_SHARED PROT_READ mapping with SetPanicOnFault: a fault of
    a gone device is EIO for the reader, not a plugin crash. Opens for writing: EROFS.
DF11 The file is the whole dax device (content agnostic), size = /sys/bus/dax/devices/<dax>/size
    for pool devices, the slice size for local slices.
DF12 fd on a numa lease keeps its text "lease <id> is not a dax lease; use env" (asserted by
    test12; still true); fd works for dax and file leases.
DF13 newFileExports never fails (it logs): a node where files/ cannot be used only loses mode
    file, and newDriver keeps its complexity.

R2 Verify in the VMs (kernel 7.3, Fedora 43, containerd, plugin as systemd-run unit):
   a. the export mounts: findmnt -t fuse.cxl-file on the node after a claim in mode file;
      the plugin log "file export: daxN.0: started (...)".
   b. containerd applies the CDI bind mount: in the reader, ls -l /run/cxl-files/<KEY>/data
      (0444, size = device size), a read and an mmap MAP_SHARED PROT_READ of the whole file
      (cxl-llm -m $CXL_<KEY>_PATH), open for writing refused (EROFS).
   c. SELinux: getenforce on both VMs; if Enforcing, ls -Z in the reader shows container_file_t,
      and the log has no "mounting with SELinux context" warning (if it has, report it).
   d. page cache: the first reader on a node grows FilePages by about the device size (512Mi,
      the whole device because of MAP_POPULATE), the second by about 0; the "holds it" line of
      the second claim shows the bytes read so far, and "stopped" the total per node.
   e. Unprepare: after the readers are deleted, no fuse.cxl-file mount is left and
      /var/lib/kubelet/plugins/cxl.generic/files/ is empty on both nodes; if an Unprepare logs
      "device or resource busy" or "is in use after the unmount", send the log.
   f. Reader pods in cached mode: the page cache is charged to the first reader of a node;
      a memory limit below the device size plus the engine (about 0.7 GiB for llm0) makes it
      read the device again; use no limit or a larger one.
   g. Optional: a lease reader, cxl-request request --serial S --shared --mode file --read-only
      --exec sh -c 'cmp /proc/self/fd/3 ...' or cxl-llm --fd 3 / -m /proc/self/fd/3 (reopening
      /proc/self/fd/3 of a regular file is expected to work).
   h. Optional: plugin restart with a reader running: log "detached 1 stale mounts", export
      started again for later readers.
R3 The device file is the whole device (536870912 bytes for llm0), GGUF at offset 0 and zeros

Findings
--------
F-1 go-fuse v2.12.0 DirectMountStrict works on the host kernel 7.0.7 as root of a user
    namespace (unshare -Urm): mount, read, mmap MAP_SHARED, EROFS on write opens, EBUSY while
    the file is open or mapped, unmount, stale detach, shutdown detach. Two reads and a mapping
    of a 3 MiB file read the "device" exactly once (24 reads, 3145728 bytes): FOPEN_KEEP_CACHE
    keeps the page cache across opens. Aborting a lingering connection through fusectl works for
    the mounting user (the copy then reads ENOTCONN).
F-2 New dependency github.com/hanwen/go-fuse/v2 v2.12.0 (BSD-3, pure Go; vendored packages fs,
    fuse, internal/*, splice; no new transitive module in the build; go.sum also lists
    github.com/moby/sys/mountinfo v0.7.2, required by go-fuse's tests only). Flag to the user
    (D4 says so).
F-3 Baseline of the tree: whole-tree golangci-lint reports only the cgo typecheck of
    pkg/fakehlml (missing hlml.h), which hides all other findings; gofmt -l lists
    cmd/kubelet-gpu-plugin/driver.go (pre-existing, untouched).
F-4 The fd of a file lease is opened through the host mount, so it pins it: releasing a file
    lease completes only after the holder closed the fd and unmapped the file (Unprepare EBUSY,
    kubelet retries; documented in LEASES.md limitations). Containers of claims use their own
    bind copies and do not pin the host mount.
F-5 Mode file on local memdevs reads zeros (no claim can write a slice it reads read-only, and
    slices are zeroed); it is there for symmetry and single-node testing (LOCAL.md says so).
F-6 The republish hook of plan-4 no longer exists (plan-5 deleted nodeState.republish); no
    export work happens under the nodeState table lock (prepareLocalMemdev and unprepare run under
    the per-claim lock only; buildClaimsCDISpec reads only the recorded Export), the pool driver
    does it under its own p.mu as all its device work, and the export table never calls back
    into a driver.
