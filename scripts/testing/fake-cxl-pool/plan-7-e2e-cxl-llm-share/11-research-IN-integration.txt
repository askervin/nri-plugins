0. Short answers
----------------
- Driver today: a shared pool device is a "cxl create-region -t ram"
  region bound to device_dax; a claim gets the char node /dev/daxX.Y
  (CDI, "r" when readOnly) and CXL_<KEY>_* env; a lease gets an open fd
  over SCM_RIGHTS, fd 3 of --exec. The refcount is implicit (a scan of
  the other prepared claims); checkSamePreparation is the only
  cross-claim rule. The plugin image is FROM scratch (kubelet-cxl-plugin
  only): no cxl, daxctl or ndctl, so pool devices need the host-process
  plugin, which is what the e2e runs (systemd-run).
- API (recommended, alternative A): two new values of mode, block (the
  block device of a persistent device: the writer) and fs (a filesystem
  the node plugin mounts: the readers), and three DeviceConfig fields that
  apply to mode fs only: fsType (erofs|ext4, "" = detect), access
  (direct = dax=always, cached = dax=never; default direct) and path
  (container path, default /run/cxl-fs/<KEY>). Env CXL_<KEY>_PATH (the
  name plan-5 reserved) plus CXL_<KEY>_ACCESS. Leases: cxl-request
  --mode fs --access ... --name NAME, protocol fields fsType, access,
  name; the mount appears at /run/cxl/fs/NAME. Phase 1: mode fs is
  read-only; writing is mode block on all hosts of the device ("flash").
- Running containers: (a) mount propagation is the fit. CDI copies mount
  options verbatim (CDI oci.go:34-41), runc applies "rslave" of a bind
  mount (RC spec_linux.go:1105-1107, rootfs_linux.go:1291-1298) and its
  default root propagation is already rslave (RC rootfs_linux.go:1023-
  1026; containerd sets nothing for CDI mounts); kubelet makes
  /var/lib/kubelet rshared (K8S pkg/kubelet/kubelet.go:1685). So a lease
  claim gets one more CDI mount, a plugin-owned host directory bound ro,
  rslave at /run/cxl/fs, and a later plugin mount under that directory
  shows up in the running container. No setns, no pid, no privileges.
  (b) a directory fd works but gives no mount point and must be a
  detached clone to avoid ".." escapes; (c) setns+move_mount is the
  dropped lease-file machinery, smaller without device nodes but still
  the most complex. P1 measurements: section 3.4.
- Node plugin work, candidate (i) erofs/ext4 on CXL pmem fsdax:
  fake-cxl-pool persistent kind ~300 lines (incl. tests), memctl pmem
  region and namespace ~350, pool driver modes block/fs with a node mount
  table ~800, leases ~350, cxl-request ~100, docs ~250: 6-8 days. (ii)
  famfs: no fake-cxl-pool change, but a patched kernel, famfs userspace
  on every node, a FUSE daemon per mount kept alive across plugin
  restarts: only if stream FA says go.
- Reader engine: ghcr.io/ggml-org/llama.cpp:light (today b11681,
  2026-10-16, amd64 ~312 MB compressed; /app/llama-cli,
  /app/llama-completion, CPU backend variants loaded at run time, haswell

1. The driver today
-------------------
1.1 Claim on a shared pool device (D/cmd/kubelet-cxl-plugin/pool.go)
- Prepare per allocation result: poolDataFor parses the controller's
  status data, only serial, shared, size (pool.go:164-168, 487-500); the
  controller also writes exclusive (P/pkg/controller/status.go:56), the
  plugin ignores it today.
- DeviceConfig {apiVersion, kind, mode, readOnly}, strict decode
  (lending.go:233-243, parseConfig 253-287); modeFor: "" = dax for shared,
  shared refuses numa, readOnly needs dax (lending.go:322-339).
- prepareDevice: waitMemdev, then mode dax = memctl.CreateRegion(memdev,
  dax) and DaxDevNumbers (pool.go:518-550); CreateRegion reuses an
  existing region (N/pkg/cxl/memctl/memctl.go:928-931) and always runs
  "cxl create-region -t ram" (memctl.go:940), then binds device_dax
  (982). memctl execs cxl and, when installed, daxctl (memctl.go:88,
  820-831), else binds through sysfs.
- CDI: one device claim-<uid>-<n> per result: env from api.Env plus the
  claim marker, and for dax a DeviceNode type "c", permissions "r" when
  readOnly (pool.go:648-668, lending.go:345-356). Spec kind
  generic/cxl-pool, file cxl-pool (pool.go:672-693).
- Env: CXL_<KEY>_{MODE,SIZE,SERIAL,SHARED,DAX|NODE,READONLY}
  (D/pkg/cxl/api/api.go:237-259); KEY = serial in upper-case hex.
- Cross-claim rules and refcounts: checkSamePreparation refuses another
  shared/exclusive or another mode on the same serial on this node,
  readOnly may differ (pool.go:441-455). The refcount is implicit:
  preparedDevice scans the other prepared claims (pool.go:425-439);
  unprepare releases the serial only if no other claim has it (612-616),
  rollback the same (459-470). State: preparedPoolClaims.json in the
  pool driver's data dir, reloaded at start (695-723; dir from
  driver.go:423-427).
1.2 Lease of a shared device (broker.go, lease_claims.go, cxl-request)
- A claim on the lease device: Prepare makes <cxl.generic data dir>/
  leases/<uid>/cxl.sock (0666) and a CDI device lease-<uid>: rbind rw of
  that directory at /run/cxl, bind ro of the host's cxl-request at
  /usr/local/bin/cxl-request, env CXL_LEASE_SOCKET=/run/cxl/cxl.sock
  (lease_claims.go:47-61, 98-124, listen 241-270, SELinux label
  container_file_t 272-283). The directory is mounted so that a
  restarted plugin can make a new socket in it (LEASES.md "Only
  containers that list the claim ...").
- Authentication: SO_PEERCRED pid (broker.go:269-285) mapped to a
  container by NRI (ContainerByPid, lend.go:394; broker.go:383-406). So
  the plugin knows the caller's pid, pod and container.
- Protocol: one JSON line each way, strict decode (broker.go:288-327,
  api.go:75-107); a Ready dax lease's response carries the open device
  (O_RDONLY for readOnly) as SCM_RIGHTS (broker.go:349-380, openDaxDevice
  1472-1524). fdOf picks Dax of a Ready lease (599-604).
- cxl-request: reads $CXL_LEASE_SOCKET, takes the first SCM_RIGHTS fd
  (main.go:353-403), --exec forks CMD with the fd as fd 3 (ExtraFiles,
  main.go:411-423) and api.ExecEnv, which turns CXL_<KEY>_DAX into
  CXL_<KEY>_FD=3 and adds CXL_LEASE (api.go:274-285).
1.3 What the node plugin image contains
- D/Dockerfile.cxl: build stage, then FROM scratch with only

2. API proposals (plan-5 vocabulary)
------------------------------------
Words kept: source, type, shared, mode ("how a container gets the
memory"), readOnly, serial, size; env CXL_<KEY>_<FIELD>; PATH reserved for
this (plan-5 02-design 9.3). "dax" is taken (mode dax, env DAX =
/dev/daxX.Y), so the page-cache switch must not be called dax: it is
called access, with the two words plan-7 already uses, direct and cached.
New device attribute persistent: true (plan-5 reserved it) on pool
memdevs with pmem capacity.

2.1 Alternative A (recommended): modes block and fs
  DeviceConfig
    mode:     numa | dax | block | fs
    readOnly: bool              dax, block, fs
    fsType:   "" | erofs | ext4 fs only; "" = what the superblock says
    access:   "" | direct | cached   fs only; "" = direct
    path:     absolute path     fs only; default /run/cxl-fs/<KEY>
  What the container gets
    block: the block device of the device's fsdax namespace, /dev/pmemX,
           CDI DeviceNode type "b" ("r" when readOnly; CDI accepts "b",
           CDI container-edits.go:107). Env MODE=block, PATH=/dev/pmemX,
           READONLY, SIZE (namespace bytes), SERIAL, SHARED.
    fs:    a directory: the node mount of the filesystem, CDI Mount
           {HostPath: node mount, ContainerPath: path, type bind,
           options [bind, ro, nosuid, nodev]}. Env MODE=fs, PATH=path,
           ACCESS=direct|cached, READONLY=1, SIZE, SERIAL, SHARED. No
           device node: the container cannot reach the block device.
  Leases
    cxl-request request --serial S --shared --read-only --mode fs
                        [--fs-type erofs] [--access cached] [--name NAME]
                        [--exec CMD...]
    protocol request fields: fsType, access, name (plus mode, readOnly,
    shared, serial as today); response field path; env as for claims with
    PATH=/run/cxl/fs/NAME (NAME default: KEY). --exec passes no fd for
    fs (the program opens files under PATH); a block lease passes the
    device fd as fd 3 and ExecEnv turns PATH into FD as it turns DAX.
  Validation (DeviceConfig texts in the style of lending.go:330-336;
  the CLI and broker texts in the style of api.go:149-181):
    V1  "DeviceConfig: invalid mode %q (numa, dax, block or fs)" and
        "invalid mode %q (numa, dax, block or fs)" - this changes the
        texts that n4-cxl-shared-2/test12:622 and test14:403 assert.
    V2  block, fs on a device without persistent memory: "DeviceConfig:
        mode %s needs a persistent device". dax and numa on a persistent
        device: "DeviceConfig: mode %s: a persistent device is used as
        block or fs" (devdax namespaces later if wanted).
    V3  "DeviceConfig: readOnly needs mode dax, block or fs".
    V4  writable block on a shared device needs the exclusive attachment
        (status data exclusive, which the controller writes for all
        hosts): "DeviceConfig: mode block: a shared device is writable
        only with all of its hosts". The same rule for leases (--shared
        without --read-only on mode block or fs is refused).
    V5  phase 1: mode fs is read-only: "DeviceConfig: mode fs is
        read-only: set readOnly: true, write with mode block". (A later
        ext4 write mount on all hosts relaxes this.)
    V6  "DeviceConfig: fsType needs mode fs", the same for access and
        path; "invalid fsType %q (erofs or ext4)", "invalid access %q
        (direct or cached)", "invalid path %q" (absolute, clean, not /,
        not under /dev, /proc, /sys, /run/cxl). CLI: "--name needs --mode
        fs", "invalid name %q" ([A-Za-z0-9._-]{1,64}, not . or ..), name
        in use by another lease of the claim: "name %q is in use".
    V7  same node, same device (checkSamePreparation): block and fs may
        not meet in practice (a writer has all hosts), but are
        compatible preparations of one pmem region; two fs claims must
        agree on fsType and access: "access %s, but another claim mounted
        it with access %s" (one superblock per block device per node:
        ext4/erofs return the existing superblock, the second mount's
        dax option cannot differ).
    V8  a reader node never creates labels: mode fs on a region without
        an fsdax namespace fails "device 0x..: no fsdax namespace (has the
        writer written it?)"; no filesystem: "device 0x..: no erofs or
        ext4 filesystem".
  Why: each mode names what the container receives (a NUMA node, a char
  device, a block device, a filesystem), so the existing rule "mode = how
  a container gets the memory" holds; access is orthogonal and only
  meaningful for fs; nothing renames.

2.2 Alternative B: plan-5's reserved mode fsdax plus a mount object
    mode: fsdax, readOnly, mount: {fsType, access, path}
  mode fsdax without mount = the block device (writer); with mount = the
  plugin's mount (readers). Matches the reservation word for word and
  keeps one mode. Against: "fsdax" is wrong for access cached (no dax at
  all) and for famfs (devdax, not an fsdax namespace); a nested object in
  an otherwise flat config; MODE=fsdax does not tell a program whether
  PATH is a device or a directory.

2.3 Alternative C: mode fs only, write mounts, plugin formats
    mode: fs, readOnly: false, fsType: ext4, format: true (writer)
  The writer copies files into a rw ext4 mount on all hosts; Unprepare
  unmounts (syncs) before the controller detaches; readers mount ro.
  Simplest for users (no images), but rules out erofs (no write mount),
  puts mkfs (e2fsprogs) into the node plugin's dependencies and makes the
  plugin decide when to format shared bytes. Worth adding later as the
  "write mount" of the task (ext4 only, V5 relaxed), not as the base.

2.4 Leases in A: the mount point
  /run/cxl/fs/NAME: next to the socket directory /run/cxl that every
  lease container already has, and next to the CLI's world. Host side:
  <cxl.generic data dir>/lease-fs/<claim uid>/ (root 0755, written only
  by the plugin), CDI mount of the lease device {HostPath that dir,
  ContainerPath /run/cxl/fs, options [rbind, ro, rslave]} added in
  leaseCDIDevice (lease_claims.go:99-123), created in OpenClaim, removed
  in CloseClaim. A separate ro host directory, not a subdirectory of the
  rw socket directory: a container could plant a symlink in the rw one
  and make the plugin mount over a host path. The mountpoint /run/cxl/fs
  itself is created by runc inside the rw /run/cxl bind (host side:
  leases/<uid>/fs, made by the plugin first). Claims use /run/cxl-fs
  (not nested in a ro lease directory, where runc could not create a
  mountpoint).


3. Mounting into a running container (leases)
---------------------------------------------
3.1 (a) Mount propagation through a CDI mount
- CDI: Mount.toOCI copies HostPath, ContainerPath, Type and Options as
  given (CDI pkg/cdi/oci.go:34-41; applied in container-edits.go:124-129,
  sorted by depth 432-470).
- containerd 2.x: CDI devices of the CRI request are injected by
  WithCDI (CD internal/cri/server/container_create_linux.go:104,
  internal/cri/opts/spec_linux.go:138-177, pkg/cdi/oci_opt.go:31-55).
  Propagation and RootfsPropagation are handled only for CRI mounts
  (spec_linux_opts.go:155-178: rprivate default, rslave + rootfs rslave
  for HostToContainer, ensureSharedOrSlave check); a CDI mount's options
  reach the OCI spec untouched and RootfsPropagation stays unset.
  (containerd's comment "default root propagation in runc is rprivate",
  line 158, does not match runc 1.3.)
- runc: options rslave/rshared/... go to Mount.PropagationFlags (RC
  spec_linux.go:57-66 mapping, 1105-1107 parse); after the bind mount,
  mountPropagate applies them (rootfs_linux.go:1269-1300). Without
  rootfsPropagation the container's root is made MS_SLAVE|MS_REC
  (rootfs_linux.go:1023-1026), only the rootfs' parent is made private
  (994-1016). So even today's lease mount without a propagation option is
  probably a slave of the host mount it came from; "rslave" makes it
  explicit and independent of runc's default.
- Host side: the source must be shared. kubelet makes its root dir
  rshared (K8S pkg/kubelet/kubelet.go:1685), and systemd makes / shared on
  Fedora.
- Flow: OpenClaim makes lease-fs/<uid>; at Ready the plugin bind-mounts
  the node mount (or a subdirectory of it) ro,nosuid,nodev at
  lease-fs/<uid>/NAME; the mount propagates into every container of that
  claim at /run/cxl/fs/NAME. Release: plain umount (no MNT_DETACH); an
  EBUSY propagates back (a busy slave makes the umount fail), the lease
  stays Releasing and is retried; never destroy the region while any
  mount of the superblock exists (3.4 M3).
- Limits: the place is fixed when the container is created (under
  /run/cxl/fs); all containers of the lease claim see the mount (as they
  share the socket); idmapped (user-namespaced) pods: runc may use a
  detached mount source (srcFile, rootfs_linux.go:131-157) whose
  propagation is private - to check (M8).
3.2 (b) A directory fd over the lease socket
- The broker passes an fd of the filesystem root; the program opens
  /proc/self/fd/3/<file> (magic link walk, no privileges, no device
  cgroup for regular files). Stock llama.cpp takes "-m
  /proc/self/fd/3/model.gguf".
- Danger: openat(fd, "..") and fchdir(fd) walk out of the container's
  root into the host tree (the CVE-2024-21626 class). Needs an fd of a
  detached clone (open_tree(OPEN_TREE_CLONE|AT_RECURSIVE), mount_setattr
  MS_PRIVATE and RDONLY, as LF 326-339) whose root has no parent mount;
  ".." at its root must stay put (measure, M5).
- No mount point at all: the fd lives only in the --exec child; "a name
  given in cxl-request" means nothing. Simple in the plugin (~60 lines),
  awkward for users and for anything that wants a path.
3.3 (c) setns + move_mount by the plugin
- LF's inMountNS/createAs/move_mount, minus mknod, device cgroup and
  capability checks: mount anywhere the requester names (a path next to
  its cwd), created with the requester's fsuid. Release: enter the
  namespace again and umount, or let the namespace die with the
  container. Per-container state, a thread in another mount namespace,
  read-only rootfs and missing target directories, user namespaces,
  crash recovery (mounts left in a namespace the plugin no longer
  tracks). ~300 lines plus tests, and the user already judged this
  family too complicated (2026-10-12).
3.4 Choice and what P1 should measure
  (a): no privileges in the container, no per-container work in the
  plugin, one more CDI mount per lease claim, host-only mount and umount.
  It fits "a mount point nearby", the name travels as protocol field
  name. (b) only as a fallback; (c) only if a free choice of the path
  becomes a requirement.
  P1, in a VM (both VMs not needed):
   M1 runc and containerd versions (runc --version, containerd --version)
      and the config.json of a lease container
      (/run/containerd/io.containerd.runtime.v2.task/k8s.io/<id>/
      config.json): rootfsPropagation, and the options of the /run/cxl
      mount.
   M2 Today's lease pod (claim on cxl-lease): on the host, mkdir and
      "mount -t tmpfs x /var/lib/kubelet/plugins/cxl.generic/leases/
      <uid>/t" - does it appear in the container's /run/cxl/t
      (propagation without any option)? findmnt -o TARGET,PROPAGATION in
      the container.
   M3 A hand-made CDI spec in /etc/cdi with a mount {HostPath D,
      ContainerPath /run/x, options [rbind, ro, rslave]}, used with
      "ctr -n k8s.io run --device <vendor/class=name> ..." (or by editing
      the plugin's spec): a later "mount --bind -o ro" of the erofs node
      mount under D appears in the container, read-only; with a process
      in the container that mmaps a file of it, "umount" on the host
      gives EBUSY, "umount -l" succeeds and the process keeps reading;
      then "cxl disable-region" must fail while the superblock lives
      (else the plugin must track it).
   M4 SELinux: getenforce in the VMs, containerd's enable_selinux; can a
      container read files of an erofs/ext4 mount as is, or does it need
      -o context=system_u:object_r:container_file_t:s0?
   M5 (b): send an fd of open_tree(OPEN_TREE_CLONE) of the node mount
      into a container (python3 socket.send_fds), open
      /proc/self/fd/N/model.gguf; openat(N, "..") must give the same
      inode as N; for comparison a plain O_PATH fd of the mount
      directory (expected to escape).
   M6 stock llama.cpp (section 5) on the mount, dax=always and
      dax=never: answer, "where" chain of the mapping, FilePages and
      memory.stat file; what path /proc/PID/maps shows when read from
      the host for a file of a bind mount in the container (container
      path or mount-relative): cxl-where.py matches maps by path today.
   M7 a "b" CDI device node rw for the writer, "r" for a reader: open
      O_RDWR refused in the reader.
   M8 optional: a pod with hostUsers: false and M3's mount.

7. Risks and open points
------------------------
1. The persistent device kind is a qemu model; real shared CXL memory
   is volatile. famfs (4.2) would be the realistic path if FA allows.
2. Labels: only the writer's node creates namespaces, before any reader
   attaches; a reader reads labels at hotplug (research B 3.2). If a
   reader was attached before the writer made the namespace, it has none
   (V8 message); the test orders writer first by exclusivity anyway.
3. Coherence: readers must never mount while a writer writes; the
   exclusive attachment of the writer ensures it in the pool, and
   cached readers keep stale pages until umount (research B 3.3).
4. Teardown safety: the region must not be released while a superblock
   of it lives (lazy umounts, a container still mapping). The plugin
   uses plain umount and fails Unprepare on EBUSY (M3 confirms what
   disable-region does otherwise).
5. The new mode texts break test12/test14 substring asserts (V1).
6. SELinux labels of the mounted filesystem (M4) may need a context=
   mount option in the plugin.
7. erofs DAX needs uncompressed, block-aligned data; 2 MiB alignment of
   the model's extent decides PMD vs 4 KiB DAX faults (FS's topic; 4 KiB
   works, research B 3.3).
8. memctl lives in nri-plugins: the driver's go.mod replace must move
   again with the memctl change.
