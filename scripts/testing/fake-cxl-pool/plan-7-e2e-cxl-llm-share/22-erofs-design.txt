plan-7 erofs: design and contract
=================================
Written 2026-10-19 (orchestrator) from 21-erofs-findings.txt and the
alternative A of 11-research-IN-integration.txt section 2.1, narrowed to
what this step needs. Every stream implements exactly these names, texts
and paths; a stream that needs a change writes a Request in its status
file and continues. Paths: N = nri-plugins, P = N/scripts/testing/fake-cxl-pool,
D = N/cmd/plugins/dra-driver-cxl, E = N/test/e2e/memory.test-suite/dra-driver-cxl.

1. The flow
-----------
  host: fake-cxl-pool-server, device llm0 {shared, persistent, 512Mi}:
        files llm0.raw (data) and llm0.lsa (labels), both shared by every
        qemu that attaches the device
  writer (VM1): claim of class cxl-pool-persistent with all hosts,
        DeviceConfig {mode: block}. The driver creates a pmem region, an
        fsdax namespace (map mem) if there is none, and gives the
        container /dev/pmemK (CDI block node, rw). The container writes
        an erofs image of the model into it and exits; Unprepare releases
        the region (labels and data stay in the files).
  readers (VM1, VM2): claims of class cxl-pool-persistent, one host each,
        DeviceConfig {mode: fs, readOnly: true, access: direct|cached}.
        The driver creates the pmem region (the namespace appears from
        the shared labels), mounts the erofs on the node once per
        (device, access): direct on /dev/pmemK with dax=always, cached on a
        read-only direct-I/O loop device over /dev/pmemK; the container
        gets that mount as a read-only bind at $CXL_<KEY>_PATH, no device
        node. Stock llama.cpp maps $CXL_<KEY>_PATH/<model>.gguf.
  Unprepare of the last claim of a (device, access) on a node unmounts it;
  of the last claim of the device on the node releases the region, only
  when nothing holds the block device any more.

3. fake-cxl-pool: persistent devices (stream P)
-----------------------------------------------
- Server config (DeviceConfig of P/pkg/server/config.go) and POST
  /api/v1/devices (api.DeviceCreate): field persistent (bool, default
  false). A persistent device must be a 256Mi multiple like every device.
- api.Device: persistent (bool, always in JSON) and lsaPath (string,
  "omitempty"): the LSA file. The LSA file is the data path with its
  extension replaced by ".lsa" (llm0.raw -> llm0.lsa; a configured file
  without extension gets ".lsa" appended), size 256 KiB, created and
  removed exactly when the data file is (same life cycle and ownership
  rules as the data file today).
- Attach: object-add memory-backend-file id=<backend id of the data>,
  mem-path=<data>, size, share=on; object-add memory-backend-file
  id=<data id>-lsa, mem-path=<lsa>, size=262144, share=on; device_add
  cxl-type3 bus=..., persistent-memdev=<data id>, lsa=<lsa id>, id=...,
  sn=<serial>. Detach: device_del, then object-del of both backends (the
  order and error handling of today's volatile path). QMP and HMP. The
  fake qemu (pkg/qemu/fake.go) accepts and checks both properties.
  Discovery of existing attachments recognizes persistent-memdev and lsa.
- Client: devices output shows persistent (table column and JSON).
- Controller: every published pool device has the attribute persistent
  (bool, false for volatile devices, 21 F14); the claim status data of a
  persistent device has "persistent": true (omitted for volatile), next
  to serial, shared, size, exclusive.
- P/README.md and P/config.example.yaml document the field and the two
  files.

4. API and DeviceConfig (stream D)
----------------------------------
pkg/cxl/api: ModeBlock = "block", ModeFs = "fs", AccessDirect = "direct",
AccessCached = "cached"; Memory gains Path and Access; Env adds, for
ModeBlock: PATH (the device node), READONLY; for ModeFs: PATH (the
directory in the container), ACCESS, READONLY ("1"). SERIAL, SHARED,
MODE, SIZE as for the other modes; SIZE of block and fs is the size of
the fsdax namespace in bytes. The lease protocol (Request validation,
cxl-request) is unchanged: modes numa and dax only, texts unchanged.

DeviceConfig (the struct both drivers decode) gains:
  access  "" | direct | cached    mode fs only; "" = direct
  path    absolute path           mode fs only; "" = /run/cxl-fs/<KEY>
The local driver (cxl.nri.io) keeps modes numa and dax and every text
(21 F15). The pool driver (cxl-pool.nri.io) accepts numa, dax, block, fs.

Pool driver texts, all prefixed "DeviceConfig: " as today; checked in
this order. Config only (before the device is waited for):
  T1 invalid mode "X" (numa, dax, block or fs)
  T2 access needs mode fs            T3 path needs mode fs
  T4 invalid access "X" (direct or cached)
  T5 invalid path "X" (an absolute path outside /dev, /proc, /sys and /run/cxl)
     (absolute, filepath.Clean(p) == p, not "/", and neither equal to
     nor under /dev, /proc, /sys or /run/cxl, compared by path
     components: /run/cxl-fs is fine)
  T6 mode fs is read-only: set readOnly: true (write the device with mode block)
  T7 readOnly needs mode dax, block or fs     (replaces "readOnly needs
     mode dax" in the pool driver; the local driver keeps its text)
From the claim status data (persistent, shared, exclusive), before the
device is waited for:
  T8 mode X needs a persistent device           (block, fs on volatile)
  T9 a persistent device needs mode block or fs (mode "", numa or dax on
     a persistent device; "" is never defaulted for persistent devices)
  T10 mode block: a shared device is writable only with all of its hosts
     (shared, not exclusive, readOnly false)
  The existing "mode %s: a shared device is used as dax only" applies to
  volatile shared devices only.
At Prepare, after the memdev appeared (device errors, no prefix change):
  T11 device 0x<serial>: <memdev> has no persistent memory   (status data
     said persistent, the memdev has no pmem capacity)
  T12 device 0x<serial>: no fsdax namespace in <ndregion>: has a writer written the device?
     (mode fs, or readOnly block, and the region has no fsdax namespace
     with map mem)
  T13 device 0x<serial>: /dev/pmemK has no erofs filesystem: <mount error>
  T14 device 0x<serial>: erofs on /dev/pmemK was mounted without DAX
     (direct: the super options lack dax=always; it is unmounted again)

5. Driver behaviour (stream D)
------------------------------
Prepare of a persistent device (pool driver):
- memctl.CreatePmemRegion (section 6): region reused if the memdev has one.
- mode block: the fsdax namespace with map mem of the region if there is
  one; else, writable only: memctl.CreateFsdaxNamespace (the writer is
  the only creator of labels, 21 F5); readOnly: T12. The container gets
  CDI DeviceNode {Path /dev/pmemK, Type "b", Major, Minor, Permissions "r"
  when readOnly} and the env of section 4.
- mode fs: the fsdax namespace (T12 if none, never created). Node mount
  per (serial, access) at <pool driver data dir>/mounts/<serial hex
  without 0x>-<access>, e.g.
  /var/lib/kubelet/plugins/cxl-pool.nri.io/mounts/c1ae0001-direct, made
  once and shared by the claims on the node:
    direct: mount /dev/pmemK, type erofs, flags MS_RDONLY|MS_NOSUID|MS_NODEV,
            data "dax=always"; then T14 if the mount's super options lack
            dax=always
    cached: a loop device: LOOP_CTL_GET_FREE on /dev/loop-control, then
            LOOP_CONFIGURE of /dev/loopN with the fd of /dev/pmemK opened
            O_RDONLY and flags LO_FLAGS_READ_ONLY|LO_FLAGS_DIRECT_IO|
            LO_FLAGS_AUTOCLEAR; mount /dev/loopN, type erofs, the same
            flags, data "dax=never"
  The container gets CDI Mount {HostPath the node mount, ContainerPath
  path, Type "bind", Options [bind, ro, nosuid, nodev]}, no device node,
  and the env of section 4. Direct and cached mounts of one device on
  one node coexist (separate superblocks, 21 F9).
- Mounting and loop setup are syscalls behind a small interface (unit
  tests use a fake); no tools in the image for them.
- The state file records per device: persistent, namespace, block device
  and its numbers, access, path, node mount, loop device. At start, a
  prepared fs device whose node mount is missing is mounted again (logged).
- checkSamePreparation: on one node, block and fs claims of a device and
  fs claims with either access are compatible (one pmem region);
  persistent and volatile preparations never meet (T8, T9).
- The Prepare log line names, for block and fs, the namespace, the block
  device, the access and the node mount.
Unprepare:
- fs: when no other prepared claim on the node uses the same (serial,
  access) node mount, unmount it with umount2(mount, 0); EBUSY fails the
  Unprepare ("device 0x<serial>: unmounting <mount>: device or resource
  busy"), kubelet retries. Never MNT_DETACH.
- Then, when no other prepared claim on the node uses the serial: wait up
  to 10 s until nothing holds /dev/pmemK (no /sys/block/loop*/loop/
  backing_file names it, and an O_RDONLY|O_EXCL open of it succeeds and
  is closed at once); else fail the Unprepare ("device 0x<serial>:
  /dev/pmemK is still in use"), kubelet retries (21 F10). Only then
  memctl.Release (disable and destroy the region, disable the memdev;
  never a namespace or label operation).
Chart, image, classes:
- deployment/helm/dra-driver-cxl/templates/daemonset.yaml: the
  kubelet-plugins volumeMount (/var/lib/kubelet/plugins) gets
  mountPropagation: Bidirectional (21 F12).
- D/Dockerfile: ndctl joins cxl and daxctl in the image (built from the
  same ndctl v85 stage, with its library closure); verify ndctl version
  in the image prints 85.
- deviceclasses.yaml: cxl-pool and cxl-pool-shared add
  && device.attributes["cxl-pool.nri.io"].persistent == false; new class
  cxl-pool-persistent:
    device.driver == "cxl-pool.nri.io" &&
    device.attributes["cxl-pool.nri.io"].type == "memdev" &&
    device.attributes["cxl-pool.nri.io"].persistent == true
  (shared or not; "hosts" capacity as for every shared device).

6. memctl additions (stream D)
------------------------------
In pkg/cxl/memctl, names may differ if documented in 24-erofs-status-D:
- Persistent(memdev) (bool, error): the memdev has pmem capacity.
- CreatePmemRegion(ctx, memdev, decoder): enable the memdev, reuse its
  region or cxl create-region -t pmem -d <root decoder with
  cap_type3_pmem> -m <memdev>; wait for the nvdimm region; returns the
  CXL region, the nvdimm region and its namespaces.
- Namespaces(ctx, ndregion): name, mode (fsdax, raw, devdax, sector),
  map (mem, dev), size, block device (/dev/pmemK). ndctl list -N -r
  or sysfs.
- CreateFsdaxNamespace(ctx, ndregion): ndctl create-namespace -f -r
  <ndregion> -m fsdax -M mem (with -e <existing namespace> to reconfigure
  one), waits for the block device.
- Release and ReleaseRegion work for pmem regions (verify; no namespace
  operations).
- A root decoder lookup that takes the region type (cap_type3_volatile or
  cap_type3_pmem).

10. Amendments (accepted during the implementation, 2026-10-19)
---------------------------------------------------------------
- Root decoders: the v7.3 attributes are cap_ram and cap_pmem (not
  cap_type3_*; status D, D1).
- SIZE of block and fs is the byte size of the fsdax namespace's block
  device (534773760 for a 512Mi device), what an image must fit (D2).
- Namespaces are read from sysfs (D3); unused mounts under mounts/ are
  unmounted at driver start (D5); the local driver refuses access and path
  with T2/T3 (D6).
- T5 also forbids /var/run/cxl: "invalid path "X" (an absolute path
  outside /dev, /proc, /sys, /run/cxl and /var/run/cxl)" (review S4).
- An existing mount at a node mount path is reused only if it is erofs
  from /dev/pmemK (direct, dax=always) or from a loop device over it
  (cached); else "device 0x<serial>: <mnt> is a <type> mount of <source>,
  not of /dev/pmemK" (or "... not of a loop device over /dev/pmemK"), and
  it is neither used nor unmounted (review R1). A restart re-mounts only
  when the device's current fsdax namespace has the recorded block device
  name and numbers (R2). One 10 s holder deadline per Unprepare or
  rollback call, also for a failed Prepare (B1, R3).
- fake-cxl-pool: attachments record their LSA backend id
  (qemuLsaObjectId) and detach deletes exactly that one (R5).
- test16 (section 8): the controller runs with -shared-hosts 6
  (DRA_CONTROLLER_ARGS of dra-install), because every claim of a shared
  device takes one host of its capacity whatever its node and test16
  holds six reader claims at once: hosts '6', validValues ['1', '6'], the
  writer claims 6. A warm-up pod per node reads the reader image's files
  before the page cache is measured. The "< 5% of the model" page cache
  proofs use the reader pod's own memory.stat file; the node total is a
  coarse bound (< 50%: no second copy; >= 90% for the first cached reader
  of a node, whose pod is also charged >= 90%). The frame proof covers all
  mappings of the model (llama.cpp unmaps the header part): every page
  present, together >= 90% of the model.
- Cached readers (after 21 F18, user: "no race, no dependency on linux
  internal logic"): no "every page present" proof for page-cached
  mappings. Instead: every present page of llama-server's model mappings
  in System RAM (>= 1 present; mappings cover >= 90% of the model);
  fincore on the node mount shows the model >= 90% resident; the read
  counter of the loop device over /dev/pmemK (the only path from the
  cached mount to CXL memory; /sys/block/loopN/stat) has read >= 90% of
  the model after the first cached reader of a node and grows < 5% for
  the second; during a 128-token completion of each cached reader the
  loop device reads < 1 MiB while frames sampled meanwhile are all System
  RAM. Direct readers keep "every page present in the CXL namespace"
  (DAX mappings are neither reclaimed nor collapsed).
