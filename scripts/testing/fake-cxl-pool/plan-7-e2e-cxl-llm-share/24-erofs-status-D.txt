3. User-visible texts (exact)
-----------------------------
Pool driver (cxl-pool.nri.io), in this order; X = the configured value:
  T1  DeviceConfig: invalid mode "X" (numa, dax, block or fs)
  T2  DeviceConfig: access needs mode fs
  T3  DeviceConfig: path needs mode fs
  T4  DeviceConfig: invalid access "X" (direct or cached)
  T5  DeviceConfig: invalid path "X" (an absolute path outside /dev, /proc, /sys and /run/cxl)
  T6  DeviceConfig: mode fs is read-only: set readOnly: true (write the device with mode block)
  T7  DeviceConfig: readOnly needs mode dax, block or fs
      (config stage: readOnly with mode numa; again after the volatile
      default: readOnly with no mode on an exclusive volatile device)
  T8  DeviceConfig: mode block needs a persistent device
      DeviceConfig: mode fs needs a persistent device
  T9  DeviceConfig: a persistent device needs mode block or fs
  T10 DeviceConfig: mode block: a shared device is writable only with all of its hosts
      DeviceConfig: mode numa: a shared device is used as dax only
      (volatile shared devices only, unchanged)
  T11 device 0x<serial>: <memN> has no persistent memory
  T12 device 0x<serial>: no fsdax namespace in <regionK>: has a writer written the device?
  T13 device 0x<serial>: /dev/pmemK has no erofs filesystem: <mount error>
      (also for access cached: the block device is named, not the loop)
  T14 device 0x<serial>: erofs on /dev/pmemK was mounted without DAX
Unprepare:
  device 0x<serial>: unmounting <node mount>: device or resource busy
  device 0x<serial>: /dev/pmemK is still in use
Prepare wraps T1-T14 as before: "cxl-pool.nri.io: preparing claim
<ns>/<name>: device <dev> serial 0x<serial>: <text>"; Unprepare:
"cxl-pool.nri.io: unpreparing claim <ns>/<name>: releasing <dev> (serial
0x<serial>): <text>" (unmount) or "...: releasing serial 0x<serial>:
<text>" (holder wait).
Local driver (cxl.nri.io): unchanged texts, mode checks first:
  DeviceConfig: invalid mode "X" (numa or dax)   (also for block and fs)
  DeviceConfig: readOnly needs mode dax
  then DeviceConfig: access needs mode fs, DeviceConfig: path needs mode fs
Lease protocol / cxl-request: unchanged (invalid mode "X" (numa or dax)).
Env (KEY = serial upper-case hex, _2... for further results):
  block: CXL_<KEY>_MODE=block, _PATH=/dev/pmemK, _READONLY=0|1, _SERIAL,
         _SHARED, _SIZE=<namespace bytes>
  fs:    CXL_<KEY>_MODE=fs, _PATH=<path, default /run/cxl-fs/<KEY>>,
         _ACCESS=direct|cached, _READONLY=1, _SERIAL, _SHARED, _SIZE

4. Node mounts and loop devices
-------------------------------
Node mount: <pool data dir>/mounts/<serial hex>-<access>, e.g.
/var/lib/kubelet/plugins/cxl-pool.nri.io/mounts/c1ae0001-direct, created
0755, removed after the unmount. One per (serial, access) on the node,
shared by its claims (a claim reuses it when /proc/self/mountinfo has an
erofs mount there).
  direct: mount("/dev/pmemK", mnt, "erofs", MS_RDONLY|MS_NOSUID|MS_NODEV,
          "dax=always"); then the super options of mountinfo must have
          dax=always, else umount2(mnt, 0) and T14.
  cached: open /dev/pmemK O_RDONLY; LOOP_CTL_GET_FREE on
          /dev/loop-control; open /dev/loopN O_RDONLY; LOOP_CONFIGURE
          {fd, lo_flags READ_ONLY|DIRECT_IO|AUTOCLEAR, lo_file_name}
          (EBUSY: next free device, up to 5 tries); a warning if
          LOOP_GET_STATUS64 shows no DIRECT_IO; mount("/dev/loopN", mnt,
          "erofs", same flags, "dax=never"); the loop fd is closed after
          the mount (autoclear: the loop goes with the unmount); on a mount
          error LOOP_CLR_FD, close, T13.
Unprepare: first, for each node mount of the claim that no other prepared
claim uses: umount2(mnt, 0) if mounted (never MNT_DETACH; an error, EBUSY,
fails the Unprepare and the serial is not released); then for each serial
of the claim that no other prepared claim uses: wait up to 10 s (poll
100 ms) until Holder(/dev/pmemK) is "" (no /sys/block/loop*/loop/
backing_file names it, and open(O_RDONLY|O_EXCL) succeeds and is closed;
ENOENT/ENXIO/ENODEV = gone = free), else "still in use"; then
memctl.Release. Rollback of a failed Prepare does the same for what it
prepared.
Restart (newPoolDriver after load): every prepared fs device whose node
mount is missing is mounted again (logged "... is not mounted, mounting it
again"; a new loop device is saved in the state); entries of mounts/ that
no prepared claim uses are unmounted (umount2 0, logged) and removed.

7. Deviations from 22, with reasons
-----------------------------------
D1 Root decoder capability: 22 says cap_type3_volatile/cap_type3_pmem; the
   v7.3 kernel has cap_ram and cap_pmem (drivers/cxl/core/port.c
   CXL_DECODER_FLAG_ATTR). RootDecoder(memdev, RegionRAM|RegionPmem) reads
   those; a decoder without the attribute is accepted (as before). The
   old code read cap_type3_volatile, which never existed (a no-op).
D2 SIZE of block and fs is the byte size of the block device of the fsdax
   namespace (sysfs class/block/pmemK/size * 512 = ndctl list "size",
   534773760 for 512 MiB with map mem), not the raw namespace size
   (536870912): that is what fits an image.
D3 Namespaces are read from sysfs (22 allowed ndctl list -N -r or sysfs):
   no exec, the probing state is visible (nd probes asynchronously).
D4 Extra state field ndRegion; the Prepare log line also names the loop
   device.
D5 At start, mounts under mounts/ that no prepared claim uses are
   unmounted (plain umount2 0, failure logged) and their directories
   removed (IN 4.1 "umount the stale ones"); 22 names only the re-mount.
   A re-mount needs /dev/pmemK: after a node reboot (region gone) it fails
   and is logged; the region is not re-created at start.
D6 The local driver refuses access and path ("access needs mode fs",
   "path needs mode fs", after its unchanged mode texts): deviceConfig is
   shared, so the strict decoder no longer refuses them as unknown fields.
D7 Order consequence: readOnly with mode numa on a shared volatile device
   now gives T7 (config stage) instead of "a shared device is used as dax
   only".
D8 docs/deployment/helm/dra-driver-cxl.md is not edited: it includes the
   chart README, where Bidirectional and ndctl are documented.
