5. Deviations and open issues
-----------------------------
D1 rpm -e of the old kernel-7.3.0_rc4 before the framework install (both
   VMs). Reason: rpm -Uvh --force over an installed package of the same
   NVR is a reinstall: rpm runs the new %post (kernel-install add
   7.3.0-rc4) and THEN the old %preun (kernel-install remove 7.3.0-rc4),
   and 20-grub.install remove deletes /boot/vmlinuz-7.3.0-rc4, its
   System.map, config and BLS entry. The VM would have rebooted into
   6.17.1 (or whatever grub falls back to). Measured in VM1 with a
   throwaway noarch RPM: install, rpm -Uvh --force of the same file
   logged "post 1, post 2, preun 1, postun 1"; and rpm -Uvh --force of
   an older version erased the newer one after the new %post (so the
   -famfs2/-fsexp removal is harmless to the new entry, as seen in the
   logs). Erasing the old package first makes the framework's install a
   plain upgrade. The test00-up error text ("remove
   ~vagrant/.vm-kernel-pkgs.installed_packages in it and run this test
   again") is therefore incomplete for Fedora: it must also say
   "sudo rpm -e kernel-<same NVR>" (or recreate the VM). Not changed
   (only the EROFS check is K's in that file); a Request below.
D2 grubby --default-kernel could not be checked between the install and
   the reboot (vm-kernel-pkgs-install reboots at once). It was checked
   before the test (the running -famfs2) and the outcome after
   (7.3.0-rc4 default, booted); add's tmp_saved_entry/55-set-boot-entry
   path is what set it.
D3 Fresh source copy ~/kbuild/src instead of ~/fsexp/linux (that tree was
   built in-tree by P1; make O= refuses a dirty source tree). Same
   v7.3-rc4 source the cached tarballs come from.
D4 test00-up header comment also mentions CONFIG_EROFS_FS (two lines).
O1 ~/.vm-kernel-pkgs.default-kernel in both VMs now says
   /boot/vmlinuz-7.3.0-rc4-famfs2, a kernel that no longer exists.
   vm-kernel-pkgs-uninstall would try grubby --set-default to it and then
   rpm -e the three packages. No test of this suite calls it; harmless
   unless someone runs it.
