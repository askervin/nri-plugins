4. Deviations and choices (none weakens a 22 assertion)
-------------------------------------------------------
- Warm-up pod llm-warm per node (no claim, the server image, reads every
  file of /app and the ldd libraries of llama-server and /app/*.so, then
  exits): the first container of an image on a node reads ~50 MB of image
  files into the page cache (P1 4.3 round B: model + ~47 MB), which alone
  is more than 5% of the model (19.8 MB). The warm-up removes that
  non-model noise; the 5% and 90% limits are as in 22.
- Direct readers are also started one by one with the page cache measured
  around each (22 asks it for the cached ones only): stricter, per node.
- Mapping size: llama.cpp unmaps the GGUF header part of its whole-file
  mapping (P1 4.3: 98.5% of the file stays mapped), so llm-where-assert
  takes every mapping of the model path, requires >= 90% of the model in
  all and every page of each present and in CHAIN. 22 says "has every
  page present": that holds per mapping.
- "the CDI device has a block node": checked as a "path: /dev/pmemN" line
  and a "type: b" line in the device's CDI YAML lines (dra-cdi-device);
  the env line CXL_..._PATH=/dev/pmemN does not match "path:".
- Extra proofs beyond 22: writer's device sha256 == image sha256; the
  container sees PATH as a ro erofs in its mountinfo; status data
  persistent True for writer and readers; data and LSA files unchanged by
  the readers; dump.erofs physical offset 2 MiB-aligned.
- The writer uses dd bs=2M conv=fsync (busybox dd of python:3-alpine;
  oflag=direct is not used: busybox support uncertain, conv=fsync is 22's
  text).
