plan-7 dynamic bind mounts: design and contract
===============================================
Written 2026-10-22 (orchestrator) from 31-dynamic-bind-mount-findings.txt
(L, M, P, R numbers below refer to it) and 22-erofs-design.txt. Every
stream implements exactly these names, texts and paths; a stream that
needs a change writes a Request in its status file and continues. Paths:
N = nri-plugins, A = N/pkg/cxl/api, C = N/cmd/cxl-request,
D = N/cmd/plugins/dra-driver-cxl, E = N/test/e2e/memory.test-suite/
dra-driver-cxl, S2 = E/n4-cxl-shared-2.

1. The flow
-----------
  pod with a claim on cxl-lease: its containers have /run/cxl (socket,
      rw) and, new, /run/cxl/fs: a read-only slave bind of the host
      directory <cxl.nri.io data dir>/lease-fs/<lease claim uid>.
  container: cxl-request request --serial 0xc1ae0001 --shared --read-only
      --mode fs [--access cached] [--name models] --exec CMD
  broker: lease L {mode fs, access, name (default L)}; companion claim
      cxl-lease-L: class cxl-pool-persistent, selector serial, shares "1"
      (with --shared), DeviceConfig {mode: fs, readOnly: true, access};
      companion pod on this node.
  pool driver (Prepare of the companion): pmem region, fsdax namespace,
      node mount mounts/<hex>-<access> as for a static fs claim (D22
      section 5); then the lease bind: MS_BIND of the node mount at
      lease-fs/<lease claim uid>/<name>, inherited flags ro,nosuid,nodev
      verified; recorded in the lendRecord; no CDI device (companion).
      OnPrepared -> Ready: response {mode fs, access, path
      /run/cxl/fs/<name>, size, serial, env}. The mount is already visible
      in the container (propagation is synchronous): CMD runs with
      CXL_<KEY>_PATH=/run/cxl/fs/<name>, CXL_<KEY>_ACCESS, _READONLY=1,
      _MODE=fs, _SIZE, _SERIAL, _SHARED, CXL_LEASE.
  container: cxl-request release --lease L (or the pod ends)
  broker: deletes the companion pod and claim.
  pool driver (Unprepare of the companion): unmount the lease bind
      (umount2 without MNT_DETACH; EBUSY while the requester has files of
      it open or mapped: the Unprepare fails, kubelet retries, the lease
      stays Releasing); then the node mount if no other prepared claim
      of the node uses it; then the region when no other prepared claim
      of the node has the serial and nothing holds /dev/pmemK (10 s
      wait), as today.
  broker: drops the lease when the companion objects are gone; removes
      lease-fs/<lease claim uid> once the lease claim is closed and no
      bind is left in it.

2. API (A/api.go, stream D)
---------------------------
- const FsDir = "/run/cxl/fs": the directory of the mounts of fs leases
  in containers of lease claims.
- Request gains Access (json "access", omitempty) and Name (json "name",
  omitempty). Response gains Access (json "access", omitempty) and Path
  (json "path", omitempty): the directory of the filesystem in the
  container, once Ready.
- Validate, texts in this order (the CLI refuses them with exit 2 before
  it connects; the plugin answers {"error": ...}):
  V1  invalid source "X" (local or pool)                     (unchanged)
  V2  invalid mode "X" (numa, dax or fs)         (was "(numa or dax)", R4)
  V3  invalid access "X" (direct or cached)
  V4  shared memory is never onlined as RAM: use mode dax     (unchanged)
  V5  access needs mode fs                   (access set, mode not fs)
  V6  name needs mode fs                     (name set, mode not fs)
  V7  invalid name "X" (letters, digits, ".", "_" and "-", not "." or "..")
      (name set: 1 to 255 bytes of [A-Za-z0-9._-], not "." and not "..")
  V8  mode fs needs readOnly                 (mode fs without readOnly)
  V9  readOnly needs mode dax or fs          (was "readOnly needs mode dax")
  V10 mode fs needs source pool              (mode fs with source local)
  V11 size or serial is required                              (unchanged)
  V12 invalid serial "X"                                      (unchanged)
  EffectiveMode is unchanged (fs is never a default: a persistent device
  needs an explicit --mode fs, as a persistent claim needs mode block or
  fs, D22 T9).
- Memory, Env, EnvList, ExecEnv: unchanged (Env already gives PATH,
  ACCESS and READONLY for ModeFs; an fs lease passes no fd).

3. cxl-request (C/main.go, stream D)
------------------------------------
- Synopsis (file comment, usage, leases.md):
    cxl-request request [--source local|pool] [--mode numa|dax|fs] [--shared] [--read-only]
                        [--access direct|cached] [--name NAME]
                        [--size SIZE] [--serial SERIAL] [--wait DURATION] [--request-id ID]
                        [--exec CMD [ARG...]]
- Options of request: --access and --name added to options[OpRequest]
  (before --size) and to values(). Help lines:
    --mode      numa (lent as a NUMA node), dax (a devdax fd) or fs (a read-only
                filesystem of a persistent pool device at /run/cxl/fs/NAME);
                default numa, dax with --shared or for a shared device
    --read-only a dax fd that allows reads only; fs needs it
    --access    fs: direct (file pages are the memory of the device) or
                cached (the page cache of the node); default direct
    --name      fs: the mount point /run/cxl/fs/NAME; default the lease id
- Behaviour: an fs lease has no fd; "request --exec" and "env --exec" run
  CMD with the environment of section 2; "fd --lease L" on an fs lease
  exits 3 with the existing text "lease L is not a dax lease; use env".
  Exit codes unchanged.
- C/main_test.go: parsing of --access and --name (also --opt=VAL), the
  option lists, the refusals V2, V3, V5-V10 with exit 2 and their texts,
  "request --mode fs --read-only ... --exec" running CMD without fd 3 and
  with CXL_<KEY>_PATH and _ACCESS from the response env.

4. Broker (D/broker.go, lease_claims.go, lease_store.go, stream D)
------------------------------------------------------------------
Directories and CDI:
- const leaseFsDirName = "lease-fs"; b.leaseFsDir(uid) =
  <DataDir>/lease-fs/<uid>. leaseClaim gains FsDir (json "fsDir",
  omitempty): the host directory, set by OpenClaim. listen (or OpenClaim)
  creates <DataDir>/leases/<uid>/fs (0755, the mount point that runc
  would create inside the rw bind) and <DataDir>/lease-fs/<uid> (0755),
  labelled like the socket directory when SELinux is enabled (R9).
- leaseCDIDevice adds, when the claim's FsDir is set, the mount
  {HostPath FsDir, ContainerPath api.FsDir, Type "bind", Options
  [rbind, ro, rslave]} after the /run/cxl mount. Old entries without
  FsDir keep today's device (their containers were created without the
  mount, R7).
- CloseClaim: after the wait as today, close the socket, remove
  <DataDir>/leases/<uid> (RemoveAll, as today: it has only the socket and
  the empty fs directory), and b.removeFsDir(uid): os.Remove of each
  entry of lease-fs/<uid> and of the directory; an entry that is a mount
  point (mountinfo has a target under the directory) is left with the
  directory, logged at V(3), removed later (below). Never RemoveAll under
  lease-fs (R3).
- b.sweepFsDirs(): for every directory under <DataDir>/lease-fs whose
  name is no claim uid of the store: removeFsDir. Called by newBroker
  (after the store is loaded) and at the end of reconcile. release()
  calls removeFsDir(l.Claim) after it dropped the lease, when the claim
  is not in the store any more and no other lease of it remains.
- The broker reads mounts with a brokerConfig.Mounts func() ([]mountInfo,
  error) (nil: /proc/self/mountinfo through parseMountInfo of mount.go;
  tests give a fake).

Leases:
- lease gains Access (json "access", omitempty), Name (json "name",
  omitempty) and Path (json "path", omitempty; the container path, set
  when Ready). lease.memory() fills Path, Access and ReadOnly for ModeFs
  (ReadOnly is true for fs). leaseInfo copies Access and Path to the
  response.
- requestLease / requestOptions: l.Access = req.Access, "" -> "direct"
  for mode fs; l.Name = req.Name. Before the lease is stored, under b.mu:
  B1  mode fs and the lease claim's FsDir is "":
      lease claim <ns>/<name> has no filesystem directory (prepared by an older driver): recreate the pod
  B2  after the id is chosen: Name "" -> the id; another lease of the
      same Claim with the same Name (any stored state):
      name "X" is in use by lease <id>
  Both are answered as {"error": ...}, nothing is stored.
- serialOptions: sliceDevice gains persistent (attribute
  device.AttrPersistent, false when absent). Checks, after the
  "not shareable", "not a local device", "not a pool device" and "of
  node X" checks and before the mode-numa check, for any device found:
  B3  device 0x<serial>: mode fs needs a persistent device    (fs, volatile)
  B4  device 0x<serial>: a persistent device needs mode fs    (persistent,
      mode not fs; "" included)
  A shared device sets l.SharedDevice; it sets l.Mode = dax only when it
  is volatile (R6). The existing early return for exclusive (not shared)
  devices must come after B3/B4.
- companionSources: mode fs -> [pool] only (errPoolDisabled when the pool
  driver is disabled). companionDevices: mode fs -> DeviceClassName
  device.ClassPoolPersistent for both sources' logic (pool only reaches
  it); selectors and capacity as today (serial selector; shares "1" with
  --shared; size selector on shared devices; memory capacity on
  exclusive devices). companionRequest: the DeviceConfig gains Access
  for mode fs; no Path (R5).
- OnLending: the lendRecord of an fs lease gets FsDir (the claim's) and
  Name. OnPrepared: for d.Mode == fs: l.Access = d.Access, l.Path =
  api.FsDir + "/" + l.Name, l.Node = -1, l.Dax = ""; a lease of mode fs
  whose device is not fs (or the reverse) is logged and made Failed with
  "companion prepared mode X, lease is mode Y" and released.
- The Ready log line names mode, access and path.
- release(): unchanged but for removeFsDir at the end. The revoke of the
  bind is the pool driver's (section 5), as the revoke of a numa node is
  the pool driver's at Unprepare too (the broker's RevokeNode before the
  deletion is an optimization for numa; fs has none).

5. Pool driver (D/pool.go, pool_persistent.go, lending.go, stream D)
--------------------------------------------------------------------
- lentDevice gains Access and NodeMount (the host path of the node
  mount); preparedPoolDevice.lent fills them. lendRecord gains FsDir
  (json "fsDir", omitempty), Name (json "name", omitempty) and Mounts
  (json "mounts", omitempty): the host paths of the lease binds.
- bindLeaseMounts(rec *lendRecord, devs []preparedPoolDevice) error, in
  pool_persistent.go, called by prepareClaim after the devices are
  prepared and before companionLender.lend, for a companion only:
  for each device of mode fs:
    E1 rec.FsDir == "": lease <id>: its lease claim has no filesystem directory
    E2 a second fs device: lease <id>: more than one filesystem device
    target = <FsDir>/<Name>; MkdirAll(target, 0755)
    if Mounted(target) != nil (a re-prepare after a crash): it must be
      erofs with the Source of the node mount (Mounted(d.NodeMount)) and
      flags ro, nosuid, nodev; else
      E3 device 0x<serial>: <target> is a <type> mount of <source>, not of <node mount>
      (neither used nor unmounted)
    else Mount(d.NodeMount, target, "", MS_BIND, "") (R1), then
      Mounted(target) must be erofs with that Source and the MountFlags
      ro, nosuid and nodev; else unmount it again, remove the directory:
      E4 device 0x<serial>: the bind of <node mount> at <target> is not a read-only nosuid nodev erofs mount
    rec.Mounts = append(rec.Mounts, target); log
    "<driver>: lease <id>: bound <node mount> at <target>".
  An error fails the Prepare like a lend error: unbindLeaseMounts(rec),
  revoke, lender.failed(lease, err), fail(err).
- unbindLeaseMounts(rec *lendRecord) error: for each path of rec.Mounts
  that Mounted(path) reports mounted: Unmount(path) (umount2 flags 0);
  an error, EBUSY included, is
    E5 lease <id>: unmounting <target>: <error>
  and stops the loop; after a successful unmount, and for a path that is
  not mounted, os.Remove(path) (ENOENT ignored). rec.Mounts is not
  changed (a retry unmounts what is left). Log "unbound <target>".
- prepareClaim: bindLeaseMounts before p.lender.lend; on any later
  failure of the same Prepare (lend error, sync error) unbind as well.
  The fail closure unbinds rec.Mounts of the lend before rollback.
- unprepareClaim: p.lender.releasing, p.lender.revoke (as today), then
  unbindLeaseMounts(pc.Lend); an error fails the Unprepare
  ("<driver>: unpreparing claim <name>: <E5>") before releaseDevices.
  Then releaseDevices as today (node mount if unused, holder wait, region).
- restoreMounts (start): after the node mounts of prepared claims are
  mounted again and before the sweep of mounts/: for every prepared
  claim with a Lend whose Mounts has a path that is not mounted: if the
  claim's fs device's node mount is mounted, bind it again (the checks
  of bindLeaseMounts) and log "bound again"; else log an error and leave
  it. Then sweep stale lease binds: every mount of /proc/self/mountinfo
  whose Target is under p.leaseFsRoot (section 6) and is in no prepared
  claim's Lend.Mounts is unmounted (no detach; an error is logged, the
  mount left for debugging) and its directory removed.
- nodeMounter gains Mounts() ([]mountInfo, error) (sysMounter has it;
  the fake of the tests too).
- checkSamePreparation, poolModeFor, ensureNodeMount, releaseDevices:
  unchanged. The companion's device records Path = the default
  /run/cxl-fs/<KEY>, unused (R5).
- The Prepare log line of a companion names the lease and the bind.
