3. Choices and interpretations (no contract name, text or path changed)
-----------------------------------------------------------------------
I1 D2.3 "no cxl-lease-* pod or claim": the companion of cached-c (VM1)
   legitimately lives until E, so D2 waits for the objects of direct-b's
   lease only and checks that cached-c's companion still runs; E waits
   for all of them.
I2 "kill llama-server (pkill llama-server)": kill -KILL of the host pid of
   llama-server (llm-server-pid) from the node, not pkill in the
   container: the llama.cpp image is not known to have procps, and a
   kubectl exec in a container whose pid 1 exits ends unreliably. SIGKILL
   makes the exit status deterministic (137, the pod Failed); SIGTERM
   would let llama-server exit 0 and the pod Succeed, against 32's
   "the pod is Failed".
I3 Extra proofs: the lease reader's log names CXL_LEASE (echo in
   reader.sh), checked against the list; the lease response has no node
   and no dax field; the companion DeviceConfig is the exact dict; the
   lease bind has the superblock options of the node mount; the pod exit
   code 137; test12's /run/cxl/fs is a slave mount (master:N) in main and
   its host directory exists and goes.
I4 The region checks of D2 use /sys/bus/cxl/devices (region*), like
   llm0-free, not cxl-dump.
