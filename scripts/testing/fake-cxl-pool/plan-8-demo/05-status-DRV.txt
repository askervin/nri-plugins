2. The published device (cxl.nri.io, a memdev listed in sharedDevices)
---------------------------------------------------------------------
  name: memdev-<lower-case hex serial>          (e.g. memdev-c100e2e1)
  attributes (exactly these six; nodeAffinity absent when unknown):
    type: {string: memdev}
    source: {string: local}
    serial: {string: "0xc100e2e1"}
    shared: {bool: true}
    size: {int: <RAM capacity of the memdev>}
    nodeAffinity: {int: N}
  allowMultipleAllocations: true
  capacity: {shares: {value: "1M"}}             (no requestPolicy)
  no memory capacity, no memoryBlockSize, no nodeAllocatableResources.
  The quantity is resource.NewQuantity(1000000, DecimalSI): String() and
  JSON both print "1M" (kubectl -o json: "capacity":{"shares":{"value":"1M"}});
  consumedCapacity of an exclusive claim is "1M", of a share "1".
  Published when listed, not ignored, not a pool device, enabled, RAM
  capacity > 0, no regions but the plugin's, and no claims hold it as
  slices. The block size is not needed (published with an unknown block
  size and any size). A sliced memdev (not listed) is hidden while claims
  hold it shared. Sliced memdevs keep their shape (shared: false).

   driver of each source {apiVersion <driver>/v1alpha1, kind
   DeviceConfig, mode dax, readOnly as requested}; a firstAvailable
   claim's configs apply to "lease/local" and "lease/pool" respectively)
----------------------------------------------------------------------
"share" = capacity: {requests: {shares: "1"}}; no capacity = exclusive.
Serial selector: device.attributes["<driver>"].serial == "0x<hex>".
Size selector on shared classes: device.attributes["<driver>"].size >= <bytes>.
A --serial that a ResourceSlice has (cxl.nri.io or the pool driver)
narrows the claim to ONE exactly request of that device's source and
class, with or without --source; firstAvailable local-then-pool remains
only for requests without --serial and for a serial that no slice has.
  request --serial S  (S shared local, the writer; --source local the same)
     exactly: class cxl-local-shared, serial selector (cxl.nri.io), no capacity
  request --serial S --shared --read-only  (S shared local)  [test18 readers]
     exactly: cxl-local-shared, serial selector, share; readOnly true
  request --serial S  (S shared pool device)  [test13/test16 writer]
     exactly: cxl-pool-shared, serial selector (cxl-pool.nri.io), no capacity
  request --serial S --shared --read-only  (S shared pool device)
     exactly: cxl-pool-shared, serial selector, share; readOnly true
  request --serial S --size N  (S exclusive local / pool device)
     exactly: cxl-local / cxl-pool, serial selector, capacity memory: N
  request --serial S --shared  (S in no slice)
     firstAvailable: [{local, cxl-local-shared, serial sel, share},
                      {pool, cxl-pool-shared, serial sel, share}]
  request --shared --size 64Mi  (no --source, no serial)
     firstAvailable: [{local, cxl-local-shared, size >= 67108864, share},
                      {pool, cxl-pool-shared, size >= 67108864, share}]
  request --source local --shared --size 64Mi
     exactly: cxl-local-shared, size >= 67108864, share
  request --shared --size N with the pool driver off
     exactly: cxl-local-shared, size sel, share (no errPoolDisabled)
  not shared, no serial (unchanged): cxl-local / cxl-pool with capacity

Matching exactly as ignoreDevices: memN, uevent name cxl/memN,

7. Deviations from PLAN9 03, with reasons
-----------------------------------------
- The shared path is a separate method AcquireShared(ctx, uid, request,
  serial, readOnly, use) instead of a shared flag on Acquire: the two
  paths share nothing but the device lookup; keeps every Acquire caller
  unchanged.
- TotalBytes = ConsumedBytes = SIZE = the size of dax0.0 (the region's
  dax device), not the memdev's RAM capacity: the restart check
  (dropGoneSlices) compares a slice with its dax device size, and the
  container maps the dax device. On the fake sysfs and for a 1G memdev
  whose region spans it they are equal (1073741824). If E2E sees a
  different SIZE than DRA_LOCAL size, this is why.
- modeFor checks readOnly before the shared rule, so a shared device
  with {mode numa, readOnly true} says "DeviceConfig: readOnly needs
  mode dax" (as plan-9 04 S4 test17 F expects); {mode numa} alone says
  "DeviceConfig: mode numa: a shared device is used as dax only". No
  effect elsewhere: modeFor(true) had no caller before.
- A --serial found in a ResourceSlice narrows the companion claim to
  one exactly request of the device's source (coordinator, 2026-10-20),
  also for exclusive devices, which before got firstAvailable with both
  sources: the scheduler never evaluates a subrequest that cannot match,
  test13/test16 companions stay one exact pool request, the demo's zoom
  shows one request. 03 section 6's firstAvailable applies to requests
  without --serial and to a serial no slice has. The lease records it in
  "deviceSource" (only when no --source was requested).
- OnPrepared also sets lease.SharedDevice from the lent device (a lease
  without a serial that lands on a shared device still reports
  SHARED=1); 03 asks lentDevices to set Shared for that purpose.
- "Logged once" is per process, per memdev name and reason.
- An idle shared device that is not configured shared (only possible
  through a direct allocator call; Reconcile releases it at start) is
  released by the next sliced Acquire.
- The sliced shape publishing after the region is destroyed happens on
  the next scan (udev event or restart), as 03 section 7 says.
