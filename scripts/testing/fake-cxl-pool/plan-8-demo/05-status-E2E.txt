Deviations from plan-9 04 S4 (with reasons)
-------------------------------------------
- test17 F "readOnly with mode numa -> 'DeviceConfig: readOnly needs
  mode dax'": not reachable on a shared device: modeFor(shared=true)
  (D/lending.go) checks "a shared device is used as dax only" before
  readOnly, so the pod gets the dax-only text; test17 asserts that text
  for mode numa + readOnly (the precedence), and adds access: cached ->
  "DeviceConfig: access needs mode fs" as the second distinct refusal.
  Not a weakening: every pod still has to be refused with an exact text.
- test17 F shares "0" is allocated "next to the readers" (as the plan
  says), not next to an exclusive holder; the guard text is asserted.
- test17 A "no nodeAllocatableResources": asserted, but the apiserver of
  these VMs drops that field anyway (DRANodeAllocatableResources off, see
  the noise comment in dra-trace-summary), so the assert cannot fail here.
- test18 follows the demo's command shapes instead of test13's: the
  writer requests without --exec and writes with "fd --lease --exec",
  releases with "release --all" (plan D "touch /tmp/done" becomes L6);
  all three readers use the demo's "--wait 0s" then "fd --lease ID --wait"
  (plan C's "--wait 300s --exec" and F's "--wait 0s ... fd" merged:
  every reader does F). The holders are started before the release, so
  the release-to-holding time is measured as in test13 D.
- test18 uses shared0 in the pool so that the firstAvailable pool
  alternative of E3 can be satisfied: E3 then proves that local comes
  first, not that the pool had nothing.
- test18 H checks the lease table through leases.json
  ({"claims":..., "leases": {id: ...}}, D/lease_store.go:123-124).

Assumptions about DRV names (from plan-9 03, as no 05-status-DRV.txt
existed when I wrote this; re-check when it does)
--------------------------------------------------------------------
- state file localDevices.json: the device entry (devices[], matched by
  "serial" (uint64) or "serialHex") has "shared": true and its claims in
  "claims" {uid: ...} like slices (03 section 5 step 3).
- region of a shared device = the whole memdev (DRA_LOCAL_SIZE), its dax
  device daxX.0 the whole region, device_dax, never resized (03 5.2).
- the CDI device of a shared local claim is claim-<uid>-0 of kind
  nri.io/cxl (spec cxl-claims, as test14), device node path /dev/daxX.0,
  "permissions: r" only when readOnly; env SERIAL SHARED=1 MODE=dax
  SIZE=<device size> DAX READONLY + the claim marker (03 section 5, 13-15).
- the guard text exactly: device <serial>: consumed shares "0" is less
  than 1: request shares: 1 (a share) or no shares (exclusive) (03
  section 8, %q of the quantity "0").
- lease response/list: "shared" = the lease's --shared flag (false for
  the writer of a shared device, lease_store.go:71 "one share of a shared
  device"), env CXL_<KEY>_SHARED=1 for every lease of a shared device.
- companion of a shared lease without --source: firstAvailable
  subrequests named local and pool (lease/local, lease/pool in
  subrequests()), each with capacity shares "1"; an exactly request
  "lease" with --source or with a serial (03 section 6).
- the DeviceClass cxl-local-shared selector contains "cxl.nri.io",
  "memdev" and "shared == true"; cxl-local contains "shared == false"
  (deviceclasses.yaml as DRV has it already).
From PCTL (05-status-PCTL.txt): shared pool devices have only capacity
shares {1M}, no policy; status data exclusive true for an exclusive
allocation, no key for a share; -shared-hosts gone.
