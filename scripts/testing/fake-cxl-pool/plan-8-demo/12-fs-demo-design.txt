A. Lease mode block (stream D)
==============================
The fd model of dax leases applied to the block device of a persistent
pool device: "cxl-request request --serial S --mode block" makes the
broker create a companion claim of class cxl-pool-persistent with
DeviceConfig {mode: block, readOnly}; the pool driver prepares it as a
block claim (pmem region, the fsdax namespace that only an exclusive
writable one creates, no CDI device for a companion); the broker opens
/dev/pmemK and sends the fd with the Ready response (SCM_RIGHTS), as for
/dev/daxX.Y; "cxl-request fd --lease L --exec CMD" gives it again.

A1 api (A/api.go)
- Validate (shared by the CLI, exit 2, and the plugin), texts in order:
  V1  invalid source "X" (local or pool)                      (unchanged)
  V2  invalid mode "X" (numa, dax, fs or block)       (was "(numa, dax or fs)")
  V3  invalid access "X" (direct or cached)                   (unchanged)
  V4  shared memory is never onlined as RAM: use mode dax     (unchanged)
  V5  access needs mode fs                                    (unchanged)
  V6  name needs mode fs                                      (unchanged)
  V7  invalid name "X" (letters, digits, ".", "_" and "-", not "." or "..")
  V8  mode fs needs readOnly                                  (unchanged)
  V8b mode block with shared needs readOnly     (shared and mode block without
      readOnly: a share of a device is read-only; the whole device, without
      --shared, may be written)
  V9  readOnly needs mode dax, fs or block       (was "readOnly needs mode dax or fs")
  V10 mode <M> needs source pool                 (M = fs or block, with source local;
      was "mode fs needs source pool")
  V11 size or serial is required                              (unchanged)
  V12 invalid serial "X"                                      (unchanged)
  EffectiveMode unchanged (block is never a default).
- Response gains Block (json "block", omitempty): /dev/pmemK of a Ready
  block lease, the host path, informational (the container has no such
  node), as Dax is for dax leases.
- Env unchanged: ModeBlock gives CXL_<KEY>_PATH (the device node path)
  and CXL_<KEY>_READONLY. ExecEnv: for every key whose CXL_<KEY>_MODE is
  block, when fd >= 0, CXL_<KEY>_PATH is replaced by CXL_<KEY>_FD=<fd>
  (as CXL_<KEY>_DAX is for dax); without an fd PATH stays (cxl-request
  env prints it).

A2 cxl-request (C/main.go)
- Synopsis: --mode numa|dax|fs|block. Help lines:
    --mode      numa (lent as a NUMA node), dax (a devdax fd), fs (a read-only
                filesystem of a persistent pool device at /run/cxl/fs/NAME) or
                block (an fd of the block device of a persistent pool device);
                default numa, dax with --shared or for a shared device
    --read-only a dax or block fd that allows reads only; fs needs it
    --exec      run CMD with the lease's environment and a dax or block lease's fd 3
- execute(): the fd goes to CMD for dax and block leases (today dax only);
  exitCode(): "fd" on a lease whose mode is neither dax nor block exits 3.
- File comment and the --exec paragraph mention block.

A3 broker (D/broker.go, lease_store.go)
- lease gains Block (json "block", omitempty): the host path of a Ready
  block lease. lease.memory(): Path = Block for ModeBlock (api.Env then
  gives PATH), ReadOnly as requested. leaseInfo copies Block.
- serialOptions: a helper persistentMode(mode) (block or fs);
  B3  device 0x<serial>: mode <M> needs a persistent device   (M = fs or block
      on a volatile device)
  B4  device 0x<serial>: a persistent device needs mode block or fs
      (a persistent device with mode "", numa or dax)
  A shared persistent device keeps the requested mode (dax only for
  volatile shared devices, as now).
- requestOptions / fsLeaseOptions: block needs the pool driver (errPoolDisabled
  when disabled, as fs); no name, no access, no FsDir needed.
- companionSources: block -> [pool]; companionDevices: block ->
  device.ClassPoolPersistent; selectors and capacity as for fs (serial
  selector; shares "1" with --shared; the whole device without).
  companionRequest: DeviceConfig {mode: block, readOnly}, no access, no
  path.
- OnLending: a block lease's lendRecord has no FsDir and no Name.
  OnPrepared: d.Mode == block -> l.Block = d.BlockDevice, l.Node = -1,
  l.Dax = ""; the fs/non-fs mismatch check stays (block is "non-fs"); a
  lease of mode block whose device is not block, or the reverse, fails as
  the fs mismatch does ("companion prepared mode X, lease is mode Y").
- fdOf: a Ready block lease -> daxFd{path: l.Block, readOnly: l.ReadOnly}
  (rename the type to leaseFd if that reads better; the field names may
  stay). waitLease(withFd): dax and block leases have an fd; the error
  for numa and fs:
      lease <id> is not a dax or block lease; use env
  (was "is not a dax lease; use env").
- respond: openDax becomes openDevice(path, readOnly): the udev wait with
  the major:minor check and the private node fallback stay for /dev/dax*
  paths; another path (/dev/pmemK) is opened with os.OpenFile (O_RDWR, or
  O_RDONLY when readOnly), retried every 100 ms for up to 5 s on ENOENT and
  ENXIO, then the error. The brokerConfig hook (tests) keeps its shape.
- The Ready log line gains block %q after dax %q:
  "lease broker: lease <id>: Ready (source S, serial S, mode M, node N,
  dax "", block "/dev/pmem0", access "", path "", B bytes)".

A4 pool driver (D/lending.go, pool.go)
- lentDevice gains BlockDevice (the host path of the block device of a
  block or fs device); preparedPoolDevice.lent fills it. Nothing else
  changes: a companion of mode block is prepared like a block claim
  (poolModeFor: block on a shared device needs exclusive or readOnly, as
  today), CDI devices dropped, released at Unprepare with the holder
  wait. A plain open fd of /dev/pmemK is not a holder (11 W5): the release
  is cooperative, documented in A5.

B. The story line pool-shared-fs (stream DEMO)
==============================================
One sentence, as before: "a container asks for CXL memory while it runs;
the scheduler gives it a share of a device only when the rules allow;
the node maps the device into the container; every sharer sees the same
bytes; readers cannot write" - here the bytes are a file system on
persistent pooled CXL memory, and "maps the device" is a mount that
appears inside the running container.

B1 The device: shared0, 256Mi, shared, persistent, serial 0xc1ae0001
(the pool demo's name and serial; the attribute persistent tells them
apart). Its files $POOL_DIR/shared0.raw and shared0.lsa are removed
before the server starts (a fresh device: no file system until the writer
makes one) and after teardown.

B2 The pods: writer on vm1, reader-a and reader-b on vm2, reader-c on vm1
(as the pool demo), each with a lease claim from the template cxl-lease,
image localhost/cxl-demo-tools:demo (C3), the tools ConfigMap at /demo.
Manifests DEMO/manifests/pool-shared-fs/{writer,readers}.yaml, the pool
ones with the image and imagePullPolicy: Never.

B3 The steps (T1, "demo pool-shared-fs"), S = 0xc1ae0001; captions are
one line of at most 50 characters; the result lines come from the
existing checks unless named:
F1 "a writer starts on vm1; it has no CXL memory yet"
   kubectl apply -f pool-shared-fs/writer.yaml
   -> "Running: writer vm1" (check_running)
   T2 writer Running, lease "-"; T3 "shared0 @pool 256Mi shared
   persistent", "no claims"; T4 vm1 and vm2 "no CXL memory"; T6 shared0
   free, "attached: nowhere", "no file system".
F2 "the writer asks for the device as a block device"
   kubectl exec writer -- cxl-request request --serial S --mode block
   -> "lease L Ready block rw (exclusive)" and "block /dev/pmem0"
   (check_lease shows resp.block)
   T2 writer "block rw excl"; T3 "exclusive: writer rw"; T4 vm1 "mem0
   c1ae0001 256M  region0 pmem 256M" / "pmem0 254M no file system"; T5
   drv "writer asks block rw excl", ctrl/pool attach lines, kern "vm1 add
   mem0 region0 pmem0", drv "writer: prepared pmem0 rw", "writer: lease
   Ready block pmem0"; T6 "attached: vm1 exclusive".
   Say: the lease is a claim of the whole device (exclusive); the node
   made a pmem region and a namespace; the writer got an fd of the block
   device, no device node.
F3 "the writer makes a file system with hello.txt in it"
   kubectl exec writer -- /demo/mkfs "Hello from the writer, $(date +%T)"
   -> the tool's line: wrote erofs (8192 bytes) with hello.txt: "Hello from the writer, 12:01:12"
   T4 vm1 "pmem0 254M erofs", "open: writer rw" while it writes; T6
   "erofs: hello.txt 32 bytes" and the text (from the backing file on
   the host: the bytes are in the pool).
F4 "three readers start: two on vm2, one on vm1"
   kubectl apply -f pool-shared-fs/readers.yaml
F5 "readers ask for the file system: they must wait"
   for r in reader-a reader-b reader-c; do kubectl exec $r -- cxl-request request --serial S --shared --read-only --mode fs --name hello --wait 0s; done
   -> "reader-a Pending, reader-b Pending, reader-c Pending" (check_leases)
   T2 three "waiting"; T3 "waiting: reader-a reader-b reader-c"; T5 sched
   "reader-a waits: cannot allocate" x3. Pause: the writer holds the
   device exclusively.
F6 "the writer is done and releases the device"
   kubectl exec writer -- cxl-request release --all
   -> "released: L Released", "readers' leases Ready after N s"
   T3 "shared: reader-a ro, reader-b ro, reader-c ro"; T2 three "fs ro
   share"; T4 vm1 and vm2: region0 pmem, "pmem0 254M erofs", "mounted:
   reader-c (dax)" / "mounted: reader-a reader-b (dax)"; T5 detach from
   vm1, attach to vm2 and vm1, "reader-a: prepared erofs direct ro",
   "reader-a: mounted hello", "reader-a: lease Ready fs hello (direct)";
   T6 "attached: vm1, vm2", the file system still there.
   Say: the device was detached and attached again; each node mounted
   the erofs once (dax=always: the file's pages are the device's
   memory) and bound it into the running containers at /run/cxl/fs/hello.
F7 "each reader reads hello.txt from its mount"
   for r in reader-a reader-b reader-c; do kubectl exec $r -- cat /run/cxl/fs/hello/hello.txt; done
   -> '3 readers read: "Hello from the writer, 12:01:12"' (check_cat: the
   three lines are equal; else "readers read different texts!")
F8 "a reader tries to write: read-only file system"
   kubectl exec reader-a -- sh -c 'echo overwrite > /run/cxl/fs/hello/hello.txt'
   -> "sh: can't create /run/cxl/fs/hello/hello.txt: Read-only file system"
   (expect_fail; check_last_line). T6 unchanged.
F9 "everything goes away"
   kubectl delete -f pool-shared-fs/
   -> "pods and leases gone after N s" (check_gone)
   T2 empty; T3 "no claims"; T4 both nodes "no CXL memory"; T6
   "attached: nowhere", state free, "erofs: hello.txt" still there: the
   file system stays in the pool's device for the next reader.
"demo pool-shared-fs N", "N-" and "--auto" as for the other cases;
"demo reset pool-shared-fs" deletes the pods and leases.

B4 The views in this case
- T2 PODS & LEASES: unchanged (lease_memory gives "block rw excl" and
  "fs ro share" from the companion's DeviceConfig).
- T3 SCHEDULER: the device row gets the word persistent when the slice
  attribute persistent is true: "shared0 @pool 256Mi shared persistent";
  the "pool ok|down" status for every pool case (the case name starts
  with "pool"). Holders as today.
- T4 NODES: a pmem region (probe C5) renders as
    vm1 mem0 c1ae0001 256M  region0 pmem 256M
        pmem0 254M erofs
        open: writer rw
        mounted: reader-c (dax)
  "pmem0 254M no file system" before the writer wrote; "open: ..." only
  while a pod process has an fd of the block device (rw if opened for
  writing); "mounted: NAME (dax)" for each lease bind of the node (NAME
  the requester pod of the lease claim, "(cached)" when the mount is on a
  loop device), "mounted: -" for none, "mounted: node mount, no lease"
  when only the node mount exists. Order vm1 then vm2 for the pool cases
  (as today). The dax lines (volatile regions) stay as they are.
- T5 TRACE: the new driver lines (C6).
- T6 POOL: as the pool demo plus the file system:
    POOL: fake-cxl-pool-server               12:01:07
    shared0 256Mi shared persistent  allocated
      attached: vm1 exclusive
      owner: writer
    erofs: hello.txt 32 bytes
      "Hello from the writer, 12:01:12"
    file /tmp/fake-cxl-pool/shared0.raw
  Before F3 the two erofs lines are one: "no file system (zeros)" when
  the first MiB is zeros, "no file system" otherwise; an erofs the reader
  cannot follow: "erofs (not readable: <why>)"; several files: one
  "name size" line each, the text of the first regular file only. The
  "at 0" lines of the pool demo are not shown in this case (offset 0 is
  the erofs's reserved area). The owner line as today (short_text of the
  server's owner).

B5 Zooms (zoom.py; "demo zoom help" lists them)
  demo zoom fs               the erofs in the pool device's backing file:
                             the superblock fields (magic, block size,
                             inodes, blocks, root nid) and every file of
                             the root directory with size and first bytes
                             (C7); "no file system" otherwise
  demo zoom mounts vm1|vm2   the node's erofs mounts: findmnt -t erofs -o
                             TARGET,SOURCE,FSTYPE,OPTIONS, the loop

  demo zoom bytes [OFFSET]   the hex dump starts at OFFSET (default 0;
                             1024 shows the erofs superblock)
  The existing zooms work unchanged (claim, env, cdi, driver, kernel, cxl,
  pool, slice, pod, last).

C7 common.py: erofs_files(data) -> {"type", "files", "error", "super":
   {...}} for the bytes DATA of the start of an erofs image: the
   superblock at 1024 (magic 0xE0F5E1E2 little-endian, blkszbits,
   root_nid, inos, blocks, meta_blkaddr, xattr_blkaddr), the root inode at
   meta_blkaddr * blocksize + root_nid * 32 (version bit 0: compact 32
   bytes, i_format u16, i_xattr_icount u16, i_mode u16, i_nlink u16,
   i_size u32, i_reserved u32, i_u u32, i_ino u32, i_uid u16, i_gid u16;
   version 1: extended 64 bytes, i_format, i_xattr_icount, i_mode,
   i_reserved, i_size u64, i_u u32, i_ino u32, i_uid u32, i_gid u32,
   mtime u64, mtime_nsec u32, i_nlink u32), data layout = bits 1-3 of
   i_format (0 plain: the data at raw_blkaddr * blocksize; 2 inline: the
   full blocks at raw_blkaddr, the tail right after the inode and its
   inline xattrs (12 + (xattr_icount - 1) * 4 bytes when xattr_icount >
   0) in the meta block), the root directory's dirents (nid u64, nameoff
   u16, file_type u8, reserved u8; names from nameoff to the next nameoff
   or the end), regular files (file_type 1) with their inode's size and
   the first 48 bytes of their data cut at the first newline, printable
   ASCII only. Other layouts and anything the data does not contain are
   reported in "error" and the file's text is "(not readable)". Tested
   in selftest with testdata/hello.erofs.hex (the 8192-byte image of
   mkfs.erofs 1.9 for a 32-byte hello.txt, written by the Dockerfile's
   image on the host with docker; the agent generates it once and stores
   the hex).
C8 test90 (setup, case pool-shared-fs): as the pool case, with the server
