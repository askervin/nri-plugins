Risks and mitigations
R1 A request of shares: "0" (or a fraction) passes the API (F33) and fits
   next to an exclusive holder (F32): the guard of 03 section 5 in both
   drivers keeps such a pod from starting (its Prepare fails, kubelet
   retries); the readers' pods in test17 F prove the scheduler side and
   the guard. A hand-written claim remains able to be scheduled; this is
   a Kubernetes validation gap worth an upstream issue (the orchestrator
   decides).
R2 D6 (hide a device while the other use has claims) and D4 (keep the
   region) are the new state logic; an old localDevices.json has no
   "shared": it loads as sliced, which is what it was. Unit-tested in S1 e.
R3 A chart and driver of different versions: an old cxl-local class
   (type only) with a new driver lets a cxl-local claim without a
   capacity request take the whole shares value of a shared device and
   fail at Prepare with the dax-only text. The chart and the driver ship
   together (helm); documented in usage.md "DeviceClasses".
R4 Readers are admitted only after the writer's claim is deallocated,
   which is after its pod object is gone: a writer pod that lingers
   delays the readers; test13 lives with it. The region is not touched
   in between any more (D4).
R5 The flipped class default (D8) breaks any user claim on
   cxl-pool-shared that relied on "no capacity = one host": nothing is
   released; test11/13/16 and the samples are the only users and are
   updated by S4 and S3.
R6 The scheduler fact F23 (device without the requested capacity is
   skipped) is read in v1.37.1; a future release could make it fatal.
   The class term shared == false keeps slice claims off shared devices
   independent of that.
R7 S2 and S5 before S1: the constants live in S1's file; temporary local
   consts avoid a merge wait (the orchestrator removes them).
R8 E/dra-install's values plumbing is new; a mistake hides as "the
   device is published sliced" in test17 A. test17 A asserts the shared
   shape first, so the failure is explicit.
R9 The demo and test18 use VM2's only local device, the same one test14
   and test15 slice; each test installs the driver with its own
   configuration, and a shared device keeps its region while configured
   (D4): a test must leave the device unconfigured (region destroyed)
   before detaching it, else fake-cxl-pool cannot hot-remove it. test17 I
   and test18 I do that; the EXIT traps check it.
R10 The quantity 1000000 prints as 1M in ResourceSlices and
   consumedCapacity; tests compare quantities, not strings, where a
   helper (quantity()) exists, and the string '1M' where not; S1 writes
   the exact string in its status.
